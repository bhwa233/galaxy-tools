# Windows traffic boundary v1

`spark233.TrafficClient.exe --bridge` implements the host native protocol v1. `init` only checks readiness; it never installs, elevates or starts capture. A business `query`/`activate` uses `activation.parameters` with the fields below. All responses echo host identity unchanged. The executable owns no renderer/window.

| command        | Parameters                                                                                                                | Result                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `status`       | `scope?: own\|machine`                                                                                                    | installed, serviceAvailable, grantedScopes, enabled, collecting, collectorEpoch, generation, quality                         |
| `enable`       | scope                                                                                                                     | persist intent and acquire a lease; explicit user action only                                                                |
| `disable`      | scope                                                                                                                     | revoke generation and flush the scope                                                                                        |
| `snapshot`     | scope, limit?: 1..200, cursor?                                                                                            | source, scope, collectorEpoch, snapshotId, windowStart, windowEnd, elapsedMs, quality, processes, totals, recent, nextCursor |
| `history`      | scope, from, to (ISO UTC), resolutionSec?: 60\|3600\|86400, processInstanceId?, groupBy?: instance\|path, limit?, cursor? | rows, coverageSummary, durableThrough, earliestAvailable, resolutionSec, nextCursor                                          |
| `connections`  | scope, processInstanceId (opaque), kind?: tcp\|udp-local\|udp-observed, limit?                                            | endpoints, nextCursor; UDP local rows have no invented remote address                                                        |
| `icons`        | scope, processInstanceIds (at most 20 opaque IDs)                                                                         | icons: [{processInstanceId, pngBase64?}]                                                                                     |
| `install`      | none                                                                                                                      | invoke the fixed adjacent elevation helper; UAC is visible                                                                   |
| `grantMachine` | none                                                                                                                      | invoke the fixed helper to grant this OS user machine scope; UAC is visible                                                  |
| `clearHistory` | scope, `confirm: true`                                                                                                    | clear only the authorized ledger; missing confirmation is rejected                                                           |

`prepareStop` flushes without revoking enabled intent or the bridge lease; a later command can resume. `stop` releases all this bridge's leases, flushes and exits. EOF also releases leases. Leases expire after 15 s and the bridge renews every 5 s; status does not implicitly enable anything. A restarting service invalidates previous leases. Explicit `disable` revokes every old lease for this SID/scope.

Process rows use `processInstanceId: string`, `pid: number`, `name: string`, `imagePath?: string`, `createdFileTime: string`, `identityState`, `rxBytes: string|null`, `txBytes: string|null`, `rxBytesPerSec: number|null`, `txBytesPerSec: number|null`. Totals have the same byte/rate fields. Rates use the actual monotonic sample duration and are null during incomplete/unavailable windows. Optional connection fields are `tcpConnections`, `udpEndpoints` and `udpFlows`; UDP flow counts require observed ETW endpoints and are null without that source. Identity is boot + PID + creation FILETIME; PID alone never grants metadata access. Own scope includes only verified caller-owned instances. Known byte counts are decimal strings, including all history rows.

Live rows additionally return `alive`, `runRxBytes`, `runTxBytes`, and `observedSince` for the process instance. Application-run fields are `appRunId`, `appRunRxBytes`, `appRunTxBytes`, `appRunStartedAt`, `appRunObservedSince`, and `appRunCoverage` (`complete` or `gap`). The application totals repeat on each live member; consumers count each distinct `appRunId` once, not once per instance or page. Runs group a scope, owner SID and normalized executable path, retain exited-member contributions, and end when all members exit. A new run starts from zero. Existing `rxBytes`/`txBytes` remain sample-window deltas. Current-run checkpoints use independent `run_*` tables and survive bridge reconnects and history clearing; service restart restores identifiable live runs and marks gaps rather than inventing unobserved bytes.

History `coverageSummary` is bounded: `{state, start, end, coveredMs, gapMs}`. Its state is `complete`, `gap` or `unavailable`; times are UTC ISO, durations are decimal strings, and `end` is clipped to the durable boundary. All overlapping intervals participate, with gaps taking precedence. History rows and summary are pinned to one database snapshot before pagination; full interval arrays are not repeated in page metadata. Older services returning `coverage` arrays remain readable by the TypeScript client.

`quality.state` describes the selected scope's latest published sampling window: a covered window returns `good`, a current gap or pending history-write failure returns `partial`, and an inactive/unavailable collector returns `unavailable`. Recovery to a covered window clears the current gap reason. `eventsLost`, `realtimeBuffersLost`, `queueDropped`, `parseErrors`, and `identityUnresolved` remain cumulative diagnostics; a nonzero counter alone does not make later windows incomplete. History coverage continues to describe the queried time range independently.

The client talks to local message-mode pipe `spark233-traffic-v1` using UTF-8 JSON lines (64 KiB per business message). Each request is `{v:1,id,op,scope,...}`; each response is `{v:1,id,ok,data}` or `{v:1,id,ok:false,error}`. Service authorization uses the authenticated pipe token; caller-supplied SID, path and PID are rejected. Operations are restricted to status/snapshot/history/connections/icons/clearHistory/lease.acquire/lease.renew/lease.release/scope.setEnabled/flush. Client-side install commands are never service RPC operations.

No remote endpoints are written to history, diagnostic logs or persistent plugin config. Both history resolution retention and incomplete coverage are explicit. No capture or history is fabricated when the service is absent, disabled, unauthorized or ETW fails.
