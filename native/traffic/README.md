# Windows process traffic service

The native boundary consists of a .NET Framework 4.8 x64 Windows service, an ordinary-user bridge and a fixed elevation helper. UI and renderer state live in the official traffic plugin. See [PROTOCOL.md](PROTOCOL.md) for native-v1 commands and DTOs.

Build with `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/native-traffic/build.ps1 -StageDirectory packages/official/traffic/native`. The script uses the checked-in NuGet lock files, puts build/restore artifacts under `local-build/spark233/native-traffic`, stages a flat x64 dependency closure and writes a UTF-8 manifest without BOM. `resources.json` includes executable hashes and source-input hashes; third-party notices remain in `native/licenses`. Use `-UpdateLock` only when intentionally maintaining the pinned dependency graph.

The repository has no existing managed ETW/SQLite collector. The wrappers `NetworkEventSource` and `HistoryStore` use maintained Microsoft TraceEvent 4.0.0 and Microsoft.Data.Sqlite 10.0.14, both MIT, rather than building ETW session management or a database engine from scratch. The tested SQLitePCLRaw runtime family resolves to 2.1.13, including the x64 native SQLite library. The full transitive graph and content hashes are committed in `packages.lock.json`; package metadata and supplied license files are copied into the staged notices.

The service starts capture only for administrator-granted caller SIDs with persistent enabled intent and a renewed 15-second bridge lease. Own scopes isolate verified process owners; machine control intent is per caller SID while the machine ledger is aggregated once. Status is a pure read. The bridge checks pipe server identity against SCM and a protected version path, sends only an identification token, and releases leases on stop or EOF. The service rejects network pipe clients, authenticates the token, and never trusts supplied SIDs, executable paths or PIDs.

The collector creates only its own unique regular ETW session. It uses the manifest provider's validated version-0 send/receive schema for TCP and UDP IPv4/IPv6, excluding connection and retransmission events. Process identity combines boot GUID, PID and creation FILETIME, and orders delayed process events by creation time. Unknown owner identity is excluded from own scope and contributes to quality gaps. The current implementation does not take over or stop an existing NT Kernel Logger and does not implement a classic kernel logger fallback.

Snapshots include live visible process instances, with bounded immutable pagination. Rates are null during unavailable or incomplete windows. Process-run and application-run counters accumulate observed ETW bytes independently of sample-window deltas; exited-member contributions remain in an active application's total. Independent SQLite run checkpoints survive bridge reconnects and history clearing. TCP and local UDP endpoint counts come from one IP Helper table scan every two seconds, followed by creation-time checks. `udpFlows` counts only recently observed remote ETW flows; `udpEndpoints` counts local UDP bindings. Remote endpoints remain in memory for 30 seconds and are never written to history.

SQLite stores every attributed traffic-bearing process instance and independently updates minute/hour/day facts in a single transaction. Retention is 48 hours, 90 days and 730 days. Immutable retry batches make commits idempotent and prevent new deltas being absorbed into an already committed retry. History rows, coverage and durable time come from one read transaction; missing coverage is returned as an explicit gap. Large queries are bounded to 100,000 rows/five seconds and ask the caller to narrow the range instead of silently truncating. Cursor pages are tied to caller, query and a 30-second expiration. Clearing history requires `confirm: true` and affects only the authorized ledger.

The helper validates and copies the same opened source handles into a private staging directory, publishes a complete protected version, then stops/configures the service. It creates files with an explicit Administrators owner and SYSTEM/Administrators DACL at creation, so an elevated caller's ordinary token does not retain owner rights over service binaries or grants. Failed upgrades attempt to restore the previous service path, grants and running state. It does not expose arbitrary SCM/file/shell operations through the query pipe. Executable directories allow ordinary-user read/execute; history and grants remain restricted to SYSTEM/Administrators. An explicit `enable` retries a failed collector using only this instance's owned ETW session; status and reconnect checks do not restart capture.

Initial isolated validation on 2026-11-01:

- Locked Release builds of Core, Client, Service and Setup passed with zero warnings/errors. The staged native closure contains 37 files, about 10.9 MB. The manifest parses with Node and has no UTF-8 BOM.
- `node scripts/native-traffic/smoke.cjs` ran real isolated service and bridge processes without SCM installation or elevation. Twelve checks passed: native-v1/PID handshake, no capture on init, rejection of supplied SID, leases, stable pagination, reversible prepare-stop, coverage advancing after flush, explicit history clear, EOF lease release, pure status reads, disable and normal shutdown. Evidence: `local-build/spark233/native-traffic/runs/b86bab50-cec3-4444-9c04-31907960eb4a/report.json`.
- `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/native-traffic/verify.ps1` passed six minimum data/lifecycle checks against isolated SQLite and process catalogs: late PID generations, byte counts above the JavaScript integer limit, idempotent commits, history scope isolation and restart durability, revoked lease generations and independent machine control intent. Evidence: `local-build/spark233/native-traffic/verification/021e945e-d08e-49e2-a7a5-676ec2f95ca6/report.json`.

The initial ETW probe returned `etw-unavailable:UnauthorizedAccessException` under an ordinary-user token. Those isolated probes did not access real notes, clipboard content or user traffic history.

Subsequent validation on the same date installed and upgraded the real SYSTEM service, queried the existing traffic history without clearing it, observed a controlled download through the ordinary-user bridge, and checked the packaged plugin through its production host and renderer. The bounded history pagination and application-run totals also passed isolated native regression checks. See [the latest validation record](../../Docs/evidence/traffic-overlay-history-run-totals-2026-11-01.md) for the evidence, exact scope and remaining acceptance work.

Service upgrade rollback, exhaustive TCP/UDP transfer attribution and overload/sleep validation remain unverified. The binaries are unsigned. The code reports unavailable/partial data rather than fabricating traffic.
