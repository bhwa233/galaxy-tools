# 插件窗口统一状态栏与桌面卡片

日期：2026-11-07

状态：方案已与用户确认，尚未实现。实施清单见 [launcher-todo.md](launcher-todo.md) 的「2026-11-07 插件窗口统一状态栏」。

## 1. 目标

桌面卡片要能显示插件的独立窗口。窗口状态（普通、置顶、常驻桌面）统一由每个窗口顶部的宿主状态栏控制。窗口在普通桌面、插件栏和桌面卡片中显示时，使用同一条状态栏、同一个窗口实例和同一份页面状态。

由此取消以下分散入口：

- 设置页「编辑桌面」全局编辑模式（[DesktopWidgetManager.tsx](../apps/desktop/src/features/desktop-layer/DesktopWidgetManager.tsx) 入口与 [LayerEditor.tsx](../apps/desktop/src/features/desktop-layer/LayerEditor.tsx) 草稿流程）。卡片改为直接通过状态栏拖动，从边缘缩放，位置自动保存。
- 插件栏面板上单独定义的图钉语义。插件栏里的图钉改为同一个窗口模式控件。

## 2. 已确认决定

1. **强制统一**：所有插件独立窗口都显示宿主状态栏，包括已声明 `titleBar: "custom"` 的 Web 插件。插件不再自绘窗口控制。
2. **窗口模式互斥**：`普通窗口` / `置顶` / `常驻桌面` 三选一，由状态栏右侧的一个模式控件切换。
3. **收藏与模式分离**：星标只用于把窗口收藏为插件栏顶部的快捷入口，不改变窗口模式，放在状态栏更多菜单和顶部添加列表中。
4. **插件栏添加入口**：插件栏顶部新增「添加插件」，列出可打开的插件窗口，支持搜索。单实例窗口已打开时直接复用。从这里首次打开的窗口默认显示在插件栏中，用户切换为「常驻桌面」后，收起插件栏时继续保留。下次呼出插件栏时恢复上次的面板排列。
5. **不复制、不重载**：切换模式、进出插件栏都只改变原窗口的属性和归属，不重新创建页面，也不在窗口之间搬移内容。输入内容、结果、选中项和正在执行的任务都要保留。
6. **临时工作界面不在范围内**：截图取框、贴图、快捷剪贴板等特殊浮层不加状态栏，继续走各自的流程。

## 3. 三类窗口的现状与接法

| 类别                                                              | 当前创建方式                                                                                                                              | 当前标题栏                                                                                      | 统一接法                                                                   |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 官方可信工作区（便签、文件搜索、剪贴板、词典翻译、OCR、截图历史） | [desktop-windows.ts](../apps/desktop/electron/host/desktop-windows.ts) 通过 `createHostWindow` 创建无边框窗口，使用宿主 preload           | 页面内的 [WorkspaceTitleBar](../apps/desktop/src/features/windows/WorkspaceTitleBar.tsx)        | 扩展 `WorkspaceTitleBar`，加入模式控件和更多菜单；不改窗口结构             |
| Web 插件（流量、快捷链接、第三方）                                | [web-host.ts](../apps/desktop/electron/plugins/web-host.ts) `open()` 直接用插件页面作为整个窗口，隔离 session，`frame` 由 `titleBar` 决定 | 原生边框，或插件自绘 [window-title-bar.tsx](../packages/ui/src/components/window-title-bar.tsx) | 改为宿主无边框壳窗口：顶部由宿主绘制状态栏，插件页面放入 `WebContentsView` |
| uTools 兼容插件                                                   | [utools-runner.cts](../apps/desktop/electron/plugins/utools-runner.cts) 壳窗口加 `WebContentsView`                                        | 宿主壳窗口自绘的 40/48px 顶部栏                                                                 | 顶部栏替换为统一状态栏组件，复用现有桌面接入                               |

官方工作区的页面本身就是宿主可信代码，状态栏可以继续在页面内渲染。Web 插件页面不可信，状态栏必须位于宿主控制的壳窗口中，插件无法绘制、遮挡或伪造这些控件。

## 4. 状态栏

视觉基线沿用 [插件独立窗口布局统一 PRD](plugin-window-layout-prd.md) 第 4 节：常规高度 48px，以便签管理为参考，拖动和双击最大化规则不变。三类窗口共用同一套视觉和状态模型。

| 区域           | 内容                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| 左侧（可拖动） | 插件图标、窗口名称；插件可设置副标题，宿主限制长度并按纯文本渲染                                      |
| 中间           | 拖动区。官方工作区按 PRD 保留原有同行业务入口；Web 插件首版不提供宿主栏内业务按钮，业务操作留在内容区 |
| 右侧：窗口模式 | 一个控件，在普通窗口、置顶、常驻桌面之间切换                                                          |
| 右侧：更多菜单 | 收藏到插件栏顶部、重新加载、插件设置、开发者工具、停止插件                                            |
| 右侧：窗口控制 | 最小化、最大化/还原、关闭；常驻桌面时隐藏最小化和最大化                                               |

常驻桌面时状态栏可以改为悬停或聚焦时才显示，让卡片平时保持简洁。这一点在最后做视觉验收时再确定。

## 5. 窗口模式与生命周期

| 操作                     | 结果                                                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 切换为置顶               | 原窗口 `alwaysOnTop`，仍是普通应用窗口                                                                                            |
| 切换为常驻桌面           | 原窗口交给桌面层管理，按桌面层的身份、Z 序和故障恢复规则显示（见 [desktop-widget-layer.md](desktop-widget-layer.md)）；不停止插件 |
| 从常驻桌面切回普通窗口   | 原窗口退出桌面层，恢复普通窗口的几何、聚焦和任务栏属性                                                                            |
| 在状态栏拖动或从边缘缩放 | 只调整当前窗口；常驻桌面和插件栏的位置分别记忆，松手后保存                                                                        |
| 收起插件栏               | 非常驻桌面的窗口隐藏，插件进程和页面状态保留                                                                                      |
| 点击关闭                 | 沿用原有关闭流程：Web 插件走 `prepareStop`，官方工作区走各自的保存和取消确认。保存失败或确认超时不能强制结束业务进程              |

设置页的桌面卡片列表保留显示、隐藏、恢复故障卡片和移除卡片的功能，不再提供全局调整模式。

## 6. Web 插件合同变化

- SDK 清单中的 `titleBar`（[packages/sdk/src/manifest.ts](../packages/sdk/src/manifest.ts)）标为废弃：`"custom"` 仍能通过校验以兼容旧包，但不再生效。宿主 API 升一个次版本，并在 [SDK README](../packages/sdk/README.md) 中说明。
- `client.window.minimize/toggleMaximize/isMaximized` 和 `client.close` 保留，改为作用于宿主壳窗口，不再要求声明 `custom`。窗口操作仍由宿主执行和校验，不接受插件传入的目标窗口、坐标或标志位。
- 新增副标题设置接口，宿主负责限制长度并按纯文本显示。
- 原先绑定在插件窗口 `webContents` 上的安全约束需要全部迁到内容视图的 `webContents`：隔离 session、请求过滤、导航与重定向拦截、`setWindowOpenHandler`、崩溃检测、DevTools 快捷键和窗口身份校验。宿主状态栏使用独立的可信 preload，不与插件 preload 共用。
- 流量监控和快捷链接删除自绘的 `WindowTitleBar` 和最大化状态同步，移除 `titleBar: "custom"`，并调整页面顶部间距。流量 HUD（桌面小组件层）不在此次改动范围内。

## 7. 代价与限制

- Web 插件窗口改为无边框后，Windows 上失去原生边框的贴靠布局弹窗，拖到屏幕边缘的贴靠和边缘缩放仍保留。官方工作区、uTools 窗口和流量监控目前已是这种体验。
- 第三方插件如果自绘了标题栏，在新版宿主中会显示两层标题栏，需要插件作者删除自绘部分。
- macOS 的窗口控制位置沿用 PRD 4.3 的约定，首轮验收以 Windows 为准。

## 8. 实施顺序

1. web-host 改为壳窗口加内容视图，状态栏先只包含窗口控制，确保与现有行为一致。
2. 抽出共用状态栏组件，供 `WorkspaceTitleBar`、web-host 壳窗口和 uTools 壳窗口使用。
3. 实现窗口模式状态机并接入桌面层；移除设置页的「编辑桌面」全局模式，插件栏图钉改为模式控件。
4. 迁移流量监控和快捷链接，废弃 `titleBar`，升级宿主 API 并更新 SDK 文档。
5. 插件栏顶部加入「添加插件」入口和收藏。
6. 最后进行 UI 自动化和视觉验收。

验证遵循 AGENTS.md：每个阶段跑类型、lint 和构建门禁；只为保存确认、权限边界（宿主状态栏不可被插件调用或伪造）和模式切换不重载页面这几项关键不变量补最少的回归测试；冒烟测试数据隔离在 `local-build/`。
