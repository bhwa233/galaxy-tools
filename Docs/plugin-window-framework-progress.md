# 插件窗口框架实施记录

日期：2026-11-11；文档核对更新：2026-11-12。分支：`codex/plugin-window-framework`，基线：`main@c2f5b72`。尚未提交或推送；本文件记录实施进度，不替代产品方案和技术方案。

## 当前实现

- Host API 1.8 / SDK 0.4 窗口声明、内容绑定、标题栏和环境能力；归一化目录复用原 widget 权限边界。
- 后台调用按活跃请求和 owner 校验窗口操作，异步调用保留来源环境；创建／恢复握手拒绝递归打开。公开命令向目标页面投递激活，普通复用不重放激活。
- 版本化实例与展示存储、串行协调、创建意图、便签幂等创建回执、保存后关闭；恢复与新建分离。
- 管理列表显示未确认的创建意图；不支持幂等确认的第三方结果不会盲目重发。保存期间或排队期间重新打开胜过旧关闭请求。
- 卡片桌面添加入口按插件和支持窗口组织，动态分组、更多插件、面板列表、关闭、自由移动和整理布局；声明式窗口支持拖动、吸附和按能力缩放。
- 官方窗口、便签和 HUD 接入；便签管理增加已有便签加入卡片桌面入口。插件按窗口声明宿主标题栏，卡片桌面限制置顶、最小化、最大化。
- 便签独立编辑器打开后管理器只读并提供定位入口；转交前保存管理器，MCP 与管理器写入保护独立编辑。UI 与 MCP 删除均先保存编辑器，成功后清理展示。
- uTools 复用一个 runner 和主窗口；兼容目录与持久实例、feature 记录、卡片展示接入。
- Explorer 子窗口顶部触发区与独立开关；锁屏、睡眠时禁用；托盘和快捷键入口保留。
- 旧窗口、widget、uTools 布局迁移先保存原始快照，提交新布局后移除旧管理记录。
- 删除／卸载清理意图保存目标实例与创建意图快照，旧清理不会波及后来新建的实例。卸载完成后先持久化精确的意图／插件成功回执，再清理展示；启动和备份恢复重新加载回执，安装索引缺席且没有回执时保留未知结果。
- 创建意图恢复在队列内重新确认记录仍然存在，并在调用前后检查维护与插件可用状态，避免并发恢复重复提交或插件失效后继续提交。

### 实现结果

- 宿主复用已有全屏窗口管理新增弹窗及菜单：主进程校验宿主来源、会话 epoch 和临时 UUID，等待各原生参与者确认输入禁用后才显示宿主弹层；阻止底层焦点、点击及抬前。关闭恢复原顺序及焦点，不改持久布局、置顶或页面挂载。仅宿主管理界面按 epoch 重建，插件内容保持原节点。
- 新增失败保留弹窗，重复点击及展示失败后的重试复用同一持久创建标识；已关闭会话的延迟启动、关闭响应不能影响新会话。官方窗口的首次就绪及主动 show/focus IPC 也遵守弹层约束，uTools 原生 runner 同样遵守 `inputBlocked`。
- 卸载在代码和可选数据删除完成后，先写入独立的持久成功回执，再确认展示清理。启动及备份恢复优先按精确回执对账；安装索引缺席但没有成功回执时保留未知结果。仅在清理布局成功提交后回收不再使用的回执。
- 迁移要求实际旧卡片成员关系，不再把普通桌面窗口误加入卡片桌面；多屏旧坐标转换使用对应显示器原点。临时对话框不迁入长期清单；只有原记录仍匹配快照摘要才退休旧记录，中断或后来变化的数据保留并报告。
- 顶部触发区只绑定有效的 Explorer 桌面父窗口，验证子窗口样式和父句柄，绑定失败不显示。DPI、工作区、显示器或 Explorer 父窗口变化时重建；不使用置顶热点，过期显示坐标不能触发错误屏幕。
- 不支持卡片桌面的业务窗口回退普通桌面并先收起卡片界面。插件页面和后台 API 打开的 `purpose: dialog` 页面复用现有独立控制器和父窗口，不写持久实例／展示，不重放业务创建命令；保留原始 JSON 参数并验证 owner 及父窗口生命周期。
- `spark233.development` 独立保存构建标识、UTC 构建时间和可选提交号，基础版本不变。同基础版本的新构建使用独立代码和缓存目录；旧时间戳构建可迁移，配置和业务数据保留。正式更新继续按发布版本比较。列表、离线目录和当前安装显示基础版本加开发标签，详情展示构建信息；正式包不带开发元数据。

1. 原生探针发现关闭新增面板后焦点恢复到了错误目标。uTools 的跨进程焦点缓存尚未收到 blur，覆盖了 Web 原生窗口刚报告的焦点。现在重排只处理层级，恢复目标优先采用当前会话的实际焦点事件记录。补强既有回归用例后，旧代码失败、修复后 9 项定向通过；最终原生探针在对话框退出 DOM 后仍确认 Web 窗口聚焦、宿主不聚焦且输入约束已解除。
2. 借用窗口在 175% 缩放下出现尺寸漂移：请求 640×480，操作系统实际接受 641×481，原实现归还后为 643×482。独立 Electron 样本确认 `getBounds`／`setBounds`、普通尺寸和内容尺寸 API 都有往返舍入误差，与[上游已确认问题](https://github.com/electron/electron/issues/51572)一致。归还原生快照时，增加仅限 Windows、小误差和有限次数的读回校正，保留窗口样式；移除卡片时也先恢复窗口属性再恢复几何。不能精确表示的整数 DIP 选择最接近结果，较大差异继续遵守系统尺寸约束。当前真实环境连续三次归还均精确保持 641×481，未扩展为其他缩放或多屏均已通过的结论。
3. 状态栏、中英文提示和移除文案中的旧「常驻桌面」称谓统一为「卡片桌面」。
4. 探针等待弹窗实际退出 DOM 后再判断焦点；关闭临时对话框时，只接受窗口已销毁且匹配自身 frame 被销毁的异常，其他错误继续失败。窗口生命周期和布局不变的断言保留。
