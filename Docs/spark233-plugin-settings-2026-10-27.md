## 1. 统一入口与页面结构

- 入口固定为“设置 → 插件管理”。进入后采用参考截图的左侧插件列表、右侧插件详情结构，在现有完整大小的设置窗口内展示。
- 左侧展示已安装插件的图标、名称、启停状态，支持搜索。安装、导入、更新检查继续使用现有管理能力。
- 右侧顶部展示所选插件名称、版本、运行状态、启用开关及“打开”按钮；没有可打开工作区的插件不展示无效打开按钮。
- 更新、卸载等低频操作归入更多菜单，继续保留进度、错误、信任确认和删除数据确认。
- 不再从插件列表弹出另一套完整配置窗口。插件工作区中的设置按钮只负责定位这里对应的插件与配置页签，不保留重复配置表单。
- 进入插件管理时仍有“返回设置”路径；具体全局导航与插件列表如何分配宽度留待视觉细化，不照搬截图中的市场、账户或会员区域，也不新增插件市场范围。

| 右侧页签   | 内容                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 配置       | 插件全部业务配置，按用途分组，默认打开此页签；没有配置项时显示说明并展示功能介绍 |
| 功能       | 插件提供的功能、命令、工作区入口及对应快捷键                                     |
| 匹配       | 触发关键词、匹配规则、适用来源应用等；插件声明与用户可编辑项明确区分             |
| 信息与权限 | 版本、安装来源、权限、更新说明、运行错误                                         |

配置表单和管理内容直接显示在详情区。目录选择、危险操作确认、恢复预览等短暂对话框继续使用已有组件。

## 2. 宿主与插件配置归属

统一的是入口、交互和保存规则，不把各插件的业务数据全部塞进宿主 AppConfig。

| 归属                         | 配置范围                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 宿主常规设置                 | 主题、语言、开机启动、关闭行为、启动器呈现、超级面板及宿主 MCP 等通用能力    |
| 宿主入口管理                 | 启动器固定、隐藏、别名、排序、关键词学习等用户偏好                           |
| 宿主数据与备份               | 全局备份、预览恢复和跨插件数据迁移；沿用现有事务与确认                       |
| 便签插件                     | 编辑、自动保存、便签字体、图片展示、提醒和便签窗口行为等业务配置             |
| 应用插件                     | 应用扫描范围及自定义程序、快捷方式、普通文档和目录入口管理                   |
| 翻译插件                     | 服务地址、模型、密钥、默认语言等翻译业务配置                                 |
| 剪贴板、搜索、截图、OCR 插件 | 各自支持的业务选项、资源和来源范围；以真实能力为准，不为了统一界面虚构配置项 |

- 原设置导航中的独立“便签设置”分类取消，便签设置入口定位“插件管理 → 便签 → 配置”。
- 原“入口管理”中自定义应用目标移到应用插件；宿主入口管理保留固定、别名等偏好。针对某个结果的快捷操作按实际归属定位，不能混淆这两类管理。
- 插件功能快捷键可在对应插件下展示和编辑，快捷键注册、冲突校验仍由宿主统一处理。通用快捷键页如保留汇总视图，应引用同一份配置，不产生两份值。
- 配置由对应插件身份隔离，其他插件不能读取。业务配置、业务数据、安装版本目录分离；更新插件包不覆盖用户配置。
- 迁移现有设置入口时保留有效用户值及数据，具体字段归属逐项核对。此要求不新增旧产品名称、旧未知配置或旧协议兼容。

## 3. 明确保存合同

### 3.1 编辑与提交

- 每个插件配置独立维护已保存值和编辑草稿。修改后显示“未保存”，提供“保存更改”和“放弃更改”。无修改时不制造保存请求。
- 编辑期间不写入插件当前生效配置，不因失焦、切换页签、关闭或临时选择目录自动提交。
- “保存更改”校验该插件本次修改涉及的字段及关联约束，成功后一次确认本次提交；服务地址、模型、密钥等关联字段不能边输入边生效。
- 保存进行中显示状态并防止重复提交；完成后明确反馈成功。保存失败保留草稿，显示字段错误或失败原因，可修正并重试，不显示虚假成功。
- “放弃更改”恢复该插件最近确认的保存值，只放弃草稿，不重置成出厂默认，不删除插件数据。
- 更新通知不得覆盖未保存草稿；其他操作已改变有效配置时，保存应检测冲突并提示重新核对，不用旧整份配置静默覆盖新值。

### 3.2 离开与关闭

切换插件、离开插件管理、关闭设置或退出应用时，若有未保存修改，统一提示：

| 选择 | 行为                                           |
| ---- | ---------------------------------------------- |
| 保存 | 先保存，成功后继续原操作；失败则停留并保留草稿 |
| 放弃 | 放弃当前草稿，再继续原操作                     |
| 取消 | 留在当前插件，保留草稿，取消原操作             |

- 同一插件内切换配置、功能、匹配等页签保留草稿，不因内容卸载而丢失，也不隐式保存。
- 外部入口请求定位另一插件时，同样经过离开确认；不能因重复打开 settings 窗口绕过草稿保护。
- 关闭窗口的所有入口共用准备流程。已有保存请求进行中时等待其结果，再判断是否仍有未保存内容。
- 备份恢复、迁移等将替换有效数据的操作，也先处理草稿及保存准备。后台准备流程不能替用户默认选择保存或放弃。

### 3.3 保存与生效

- 可以立即应用的配置，在保存成功后通知对应插件生效；正在运行的任务遵循既有任务合同，不在半途中无提示地换参数。
- 需要重启插件的配置，在提交前明确提示；保存后显示“已保存，需重启生效”，由用户确认重启。若暂不重启，当前运行实例仍使用旧配置，页面不能声称新值已经生效。
- 重启遵循已有保存、拒绝、取消和排空机制。重启失败分别展示“配置已保存”和“插件未恢复运行”，保留错误与重试入口。
- 停用插件仍可编辑并保存配置，不为展示配置自动启动业务后台；下次启用加载已保存值。不具备离线配置能力的项目应说明限制，不能暗中启用插件。

## 4. 独立操作与敏感字段

- 插件启停、打开、更新、卸载是独立管理操作，不与“保存更改”批量提交，也不自动保存草稿。会使草稿失效或离开当前插件的操作必须先执行草稿确认。
- 功能执行、重建索引、清空历史、下载资源等属于明确业务操作，不能被配置保存顺带触发；危险操作继续单独确认。
- 配置表单里的“清除密钥”等修改只更改草稿，保存后才提交；取消编辑不能删除实际密钥。
- 密钥等敏感项由既有安全存储机制持有。页面显示已配置状态，提供替换和清除，不回传原密钥；日志、错误及诊断不暴露密钥。
- 新输入的密钥仅用于本次编辑和明确提交，不出现在 URL、事件广播或通用配置快照中。密钥与普通字段保存的失败一致性需在具体接口设计中落实，不能部分写入后冒充整体成功。
- 普通配置保存不能借修改关键词、路径或按钮扩大插件权限。原生信任、文件授权和权限变更仍执行既有宿主确认与校验。

## 5. 实施前缺口与本轮接口落实

实施前插件管理已有列表、启停、安装、更新、卸载、包任务及错误展示，但缺少统一配置读取/校验/保存合同。本轮已增加宿主专用 `plugin_settings_get` / `plugin_settings_save`：验证插件安装身份，返回受限字段及不透明版本，串行校验保存并拒绝旧编辑覆盖；敏感字段不回传。

本轮已按实际能力落实以下边界；具体源码及验证见实施记录：

1. 便签、剪贴板、搜索和翻译复用各自真实配置；应用入口沿用既有目标模型并加入版本校验。截图/OCR 未声明额外业务字段，显示说明而不虚构配置。
2. 当前由宿主注册官方插件字段适配器，复用已有 UI 原语与后端校验。未声明配置的第三方插件显示无配置项；可扩展的第三方清单字段协议不作为已经实现的能力，不执行任意插件表单脚本。
3. 使用安装身份与配置内容生成不透明版本，串行提交并检查并发冲突；停用配置不启动业务后台。当前可编辑字段即时应用或在下次任务读取，没有新增必须重启的配置项。
4. 搜索原生服务范围与重建作为独立操作保留原授权；截图/OCR 保留既有功能、快捷键及原生工具能力边界。

本文件不预先承诺新增依赖、不确定新的 schema 库或第三方设置框架。复杂控件复用既有业务组件，通用字段按现有表单能力实现。
