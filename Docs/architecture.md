# 当前架构

spark233 是 Windows 11 x64 启动器和插件工具集。应用使用 Electron、React、TypeScript 和 Vite；SDK、UI 和官方插件处于同一个 pnpm workspace。

## 目录与责任

| 目录                         | 责任                                          |
| ---------------------------- | --------------------------------------------- |
| `apps/desktop/electron`      | 启动、窗口、IPC、系统集成、MCP 与插件生命周期 |
| `apps/desktop/src/features`  | 按功能组织的 UI、API 适配和状态               |
| `apps/desktop/src/platform`  | renderer 与 preload 的受控桥接                |
| `packages/sdk`               | 插件清单、数据类型、Web 客户端和 native 协议  |
| `packages/ui`                | 共享组件、语义样式与主题合同                  |
| `packages/official`          | 便签、截图、OCR、翻译、剪贴板、应用和搜索插件 |
| `native`、`scripts/native-*` | 原生适配、锁定来源与构建资源                  |

启动器、设置页由 `spark233://app` 提供；笔记页面由 `spark233://notes` 提供；官方工作区和外部 Web 插件使用各自受控入口。注册窗口、主 frame 和 origin 在主进程重新验证，来源路径不能替代命令授权。

## 查询与写入

输入进入启动器查询会话，提供方按 session、request 和 revision 发布增量结果。不同调用方的查询相互独立。执行动作使用独立身份，不能废弃仍在返回的查询分组。

便签通过主进程调用隔离后台。当前草稿先排队保存，目标加载完成时再验证身份和草稿是否变化；保存失败或加载期间继续输入都会保留草稿。外部文件重载也验证保存状态和请求是否仍有效。

## 生命周期与恢复

停止插件分为准备保存、释放资源和确认进程退出。拒绝或超时不代表保存成功，不能自动强杀正常业务进程。纯宿主清理在插件已经停止后尽力完成，避免留下无法使用的半退出应用。

备份验证路径、哈希、代码清单和配置，在隔离 stage 中准备，再交换目录。回滚失败时保持维护状态，禁止在不完整目录上重启插件。备份不能增加当前未确认的插件权限或执行代码信任；需要先通过安装流程审查相应版本。恢复日志保留人工恢复依据。

## 验证和范围

类型检查、lint、格式检查、Node 测试、Chromium UI 测试与打包分别提供不同证据。真实 UAC、SYSTEM 服务、输入法、多屏、物理剪贴板与安装包验收需要独立确认；本地构建成功不等同于这些验证已经通过。
