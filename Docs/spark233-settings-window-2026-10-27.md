## 2. 窗口行为

### 2.1 打开与切换

- 启动器顶部移除独立的“入口管理、备份、插件”按钮，保留“设置”。该按钮调用宿主 `settings_open`，默认打开“常规设置”。上下文清除、窗口控制等业务按钮不受影响。
- 便签管理器设置入口调用同一命令，默认定位“插件管理 → 便签 → 配置”。
- 整个应用只存在一个标签为 `settings` 的设置窗口。重复打开时恢复、显示并聚焦现有窗口，切换到请求的页面，不重载页面、不清空未保存输入。
- 首次打开通过 URL 路由传递页面；已存在窗口通过宿主事件切换。页面尚未就绪时，由宿主保留最新请求并在就绪后交付，避免丢失入口意图。
- 一级页面标识固定为 `general`、`entries`、`plugins`、`backup`、`diagnostics`，插件页另外携带经宿主校验的插件身份及页签。无页面采用 `general`；非法 IPC 参数明确拒绝。页面解析非法 URL 页面时回到 `general`。不再保留独立的 `notes` 一级分类；这取代此前初稿导航方案。
- 重复打开请求定位其他插件或离开当前管理页时，必须先处理未保存插件草稿，不能强制跳转丢弃输入。

### 2.2 统一设置导航

设置窗口采用左侧分类导航、右侧内容区；小屏幕可收敛导航宽度，内容仍在当前窗口切换。

| 分类       | 整合内容                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 常规设置   | 原应用分组的外观、快捷键、超级面板和其他宿主通用设置                                                       |
| 入口管理   | 宿主的启动器固定、隐藏、别名、排序、关键词学习等偏好；自定义应用目标移入应用插件配置                       |
| 插件管理   | 左侧插件列表、右侧详情；统一承载插件配置、功能、匹配、信息与权限，以及既有启停、安装、更新、卸载与状态错误 |
| 数据与备份 | 备份导出、预览、选择与恢复，以及数据目录迁移；迁移入口集中到此，不在常规页重复展示                         |
| 诊断       | 现有诊断信息、检查及导出能力                                                                               |

- 管理列表和编辑内容直接呈现在右侧页面，不采用“进入设置后再弹出另一套完整管理 Dialog”的形式。提取既有业务内容供页面复用，不复制一套管理状态或后端接口。
- 目录选择、危险操作确认、恢复预览等确有上下文需要的短暂对话框继续复用现有组件与校验。
- 候选条目的快捷管理按归属定位：固定/别名等进入宿主“入口管理”，自定义应用目标进入“插件管理 → 应用 → 配置”；不再打开旧管理窗口。条目标识由现有宿主数据校验，不扩大调用权限。
- 页内切换不能丢弃尚未保存的输入；插件操作、备份恢复等进行中任务继续遵循各自生命周期和关闭准备规则，不因切换分类绕过等待或确认。

### 2.3 大小与布局

- 默认大小 1080×760，通常最小大小 800×600；均为 Electron 窗口尺寸。小屏幕下将初始大小和最小限制收敛到当前显示器可用工作区，保证窗口可见、可操作。
- 首次打开在适用显示器工作区内居中。现有窗口重复打开保留当前位置和大小；本轮不新增跨启动的窗口尺寸配置或旧配置兼容逻辑。
- 使用普通任务栏窗口，不强制置顶。支持拖动、调整大小、最小化、最大化/还原及关闭；复用已有窗口控制能力。
- 设置页面填满窗口，采用“窗口标题与控制、左侧分类导航、右侧可滚动内容”的结构。标题、导航和错误提示可见，内容独立滚动，不再套窄 Dialog 或 360px 侧栏。
- 复用 `SettingsPanel`、既有 UI 原语和主题。宽窗口允许响应式分栏，窄窗口回落单栏；长路径、较长说明和高缩放下不应撑出横向滚动或遮住操作按钮。

### 2.4 关闭与应用退出

- 关闭设置只关闭该窗口，不退出应用，不受“关闭主界面退出”选项影响。
- 窗口关闭按钮、系统关闭以及既有 `window_control.close` 走相同保存准备规则，不能从某个入口绕过等待写入。
- 关闭前等待已接受的配置写入和正在执行的迁移。失败时保留窗口和具体错误，允许用户重试，不把关闭当成保存成功。
- 插件有未保存草稿时，关闭前提示“保存 / 放弃 / 取消”；保存失败不得继续关闭。不能把宿主自动保存规则应用到插件草稿。
- 退出应用、备份恢复等既有宿主准备流程也必须等待设置页写入；正常关闭成功后释放实例，下次重新打开读取最新配置。

## 3. 配置保存与数据迁移

### 3.1 宿主配置加载和自动保存

本节只适用于宿主常规配置。插件业务配置采用下节明确保存，不因编辑或失焦提交。

1. 首次加载配置时显示加载状态。读取失败显示明确错误与重试入口，不能用空配置覆盖磁盘数据。
2. 继续采用现有自动保存，只提交用户修改字段的 patch；嵌套字段遵守现有合并合同，不提交过期的整份配置覆盖其他窗口更新。
3. 同一设置窗口的写入串行提交，页面保留用户最新输入。旧响应不能把较新的输入回滚。
4. 保存失败时保留失败字段及错误，标记仍有待保存内容。修正或重试应覆盖尚未成功的修改；其他字段保存成功不能掩盖此前失败。
5. 关闭准备等待队列清空，并检查是否仍有失败或未提交修改。有则拒绝关闭并定位错误；全部成功才允许释放窗口。
6. 来自其他窗口的配置更新继续使用现有通知机制；不得覆盖本窗口尚未完成的编辑。尽量复用现有字段 patch、世代检查和关闭准备机制，不引入第二套配置存储。

### 3.2 插件配置明确保存

- 插件配置统一位于“插件管理 → 对应插件 → 配置”，提供未保存状态、“保存更改”和“放弃更改”。编辑不影响当前运行配置。
- 保存校验失败或提交失败时保留输入；切换插件、离开页面及关闭窗口时提示“保存 / 放弃 / 取消”。同插件切换页签保留草稿。
- 需要重启生效的配置明确提示，由用户确认重启；保存成功与实际生效分别展示。
- 插件启停、更新、卸载是独立操作，不随配置保存提交，也不隐式保存草稿。完整生命周期、敏感字段及并发规则见[插件配置方案](spark233-plugin-settings-2026-10-27.md)。

### 3.3 数据目录迁移

- 继续通过宿主目录选择器授权目标目录，在设置窗口内展示目标并明确确认；取消选择或确认不启动迁移。
- 提交迁移前先完成配置写入；迁移期间禁用重复提交及会改变迁移前提的操作，关闭请求等待当前操作结束。
- 未保存插件草稿先交由用户选择保存、放弃或取消，再进入迁移；不得默认替用户保存。
- 迁移由现有宿主事务处理。成功后显示宿主返回的有效路径；失败时显示错误，不提前切换页面中的有效目录，不清理用户原数据。
- 复用现有目录校验、准备/排空、回滚与配置广播能力。本轮只改变入口承载位置，不另建文件搬运实现。

## 4. 宿主、权限与插件边界

- 复用现有宿主 Layout，以 `view: "launcher"` 保持宿主角色，通过 `hostPage: "settings"` 标记页面，渲染路由为 `view=settings`。设置窗口不是便签、胶囊或插件工作区。
- `settings_open` 仅允许已有宿主管理角色调用。设置页复用现有 preload、bridge 和配置命令授权，不新增插件访问配置的权限，不从 URL 或事件接受任意窗口地址。
- 明确检查窗口创建、尺寸限制、就绪、聚焦、关闭、崩溃和释放分支；不能仅靠 launcher 分类推断所有生命周期行为都正确。
- 设置窗口不写入便签布局，不因其打开、移动、缩放或关闭触发便签布局持久化。停用、更新便签插件时保留设置窗口；便签未就绪也能打开宿主设置。
- 保留插件管理、应用入口、备份、诊断、超级面板及其他现有设置能力，按宿主/插件归属统一归入上述页面。停用插件仍可管理其配置，但不为编辑而自动启动业务后台。
- 移除原设置弹框和侧栏时，保留便签管理器用于主题、字体和其他便签行为的配置状态，保留“关于”侧栏及原有便签保存准备。

## 7. Windows 原生资源与打包

### 7.1 先定位当前问题

- 检查 applications、clipboard、ocr、screenshot、search 原生负载和对应 `resources.json` 的匹配关系、输入摘要及实际构建错误。当前文件存在，仍须以构建校验结果判断可用性。
- 原生资源生成使用既有 Windows 工具链与构建入口。缺失时修复生成或复制路径，不用空文件、不禁用完整性校验、不删除失败记录。
- 核对 UNC → Windows staging 的 `/MIR` 行为：只有确认为构建所需、且来源和完整性可追溯的 Windows 生成文件才保留；过期输出仍须移除，不能为避免删除而保留全部旧文件。
- Linux 与 Windows 的 `node_modules` 保持分离。Windows 生成的 SQLite 与 provenance 作为经校验的一对处理，不能只复制一半或混用 Linux 结果。私有 `.workbuddy/` 等任务目录不进入构建输入。

### 7.2 统一构建与交付
