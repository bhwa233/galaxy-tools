## 1. 已确认范围与待验证选型

### 1.1 已确认的产品与技术方向

- 项目整体更名为 spark233，安装身份、内部命名和默认数据目录一并换新，不承担旧版花笺的兼容和自动迁移；已有文件不因更名而删除。正式目标平台为 Windows 11 x64。
- 项目演进为桌面启动器，主界面参考 uTools，关键词与上下文匹配参考 Rubick：根据关键词、文本特征与文件或图片上下文匹配命令和插件，再进入对应工作区。
- 一期同时交付宿主、便签、截图、OCR、翻译与词典、剪贴板、应用搜索、文件与正文搜索。各项业务均以可独立启停和更新的插件提供。
- 输入英文单词自动展示本地词典结果与翻译动作；输入句子提供 AI 翻译动作；输入文件搜索关键词可以进入专门模式。默认入口不强制混合所有正文来源。
- 截图已确定采用 xland/ScreenCapture，作为截图插件管理的外部原生程序。eSearch 整套截图子系统不再作为一期集成方案。
- 截图体验对齐微信截图的常用功能：选区、窗口识别、调整、常用标注、撤销重做、复制、保存、取消，以及截图内直接提取文字。
- 取字由独立 OCR 插件封装配套 ImageReader，支持全部复制和选取部分文字复制，并可发送词典、AI 翻译或便签。关闭 OCR 后基础截图和标注继续工作。
- 复杂贴图、透明度与穿透管理、长截图、录屏、GIF、图片美化和屏幕翻译覆盖均不作为一期截图必需能力。
- 实施前先将当前运行时与直接依赖升级到最新稳定版并验证现有应用，具体版本快照及兼容任务见实施 TODO。
- 前端使用 React、TypeScript、Vite、Tailwind CSS 与 shadcn/ui；ScreenCapture 的原生工作面保持原生界面。
- 界面采用 shadcn 组件与 Vercel/Geist 的克制工具界面方向，强调色沿用当前项目竹绿色及其深浅色变体；官方插件共享主题、组件规范与交互验收标准，见第 3.4 节。
- 插件采用 npm 包发布和分发，支持在线检查更新及本地 .tgz 导入。取消 Cloudflare 服务和自建网页发布后台，不自建插件 registry。
- 每个插件独立构建、版本化和安装，预装插件也必须支持单独更新。定义自己的宿主插件合同，不以兼容 uTools API 或任意 npm 包即插即用为目标。
- 翻译采用本地单词词典与 AI 模型双通道，支持配置服务地址、模型和密钥，不以聚合传统翻译 API 为主。
- 文件名与正文检索复用 Pulse 原生后端：默认纳入在线固定和移动 NTFS 卷，正文使用查询时按需读取的 Instant 模式，范围跟随启用卷与排除设置。服务安装时进行管理员授权；后续服务本体升级也可能需要授权。
- 保留便签独立窗口、胶囊、提醒与 Markdown 文件存储能力；工程拆分可复用当前数据模型，不将旧版安装身份或自动迁移作为交付条件。便签、剪贴板与文件内容在各自搜索模式可用，搜索来源接口仍可统一复用。
- 标准安装包携带七个官方插件、截图程序、内嵌 OCR 模型和 ECDICT 基础约 76 万词条词库；默认启用全部业务插件，后台按需启动。完整词库作为后续可选资源，AI 翻译需联网配置。
- 剪贴板逻辑与功能参考 QcClip，核心记录回贴、收藏置顶、标签备注、编辑恢复、批量合并、图库、表情符号和便捷粘贴小窗均纳入一期；默认不限历史天数和条数，采用待清理与主动清理语义。
- 插件自动检查更新，由用户确认安装；第三方 Node 后台和原生程序需用户显式信任，更新新增能力需重新确认。
- 优先复用现成组件与产品。使用 ScreenCapture 不要求用户额外手动安装该程序，由对应 npm 插件包管理所选版本及资源。

一期完成指第 14 节全部实施阶段和必需链路通过验收。开发可以分批，但取字、翻译、剪贴板和插件独立更新均属于一期完成条件。

### 1.3 产品身份、首装与默认状态

2026-10-25 确认：产品界面仅维护简体中文（`zh-CN`）和英文（`en-US`），不提供第三种界面语言；其他中文地区设置统一使用简体中文，英语地区设置统一使用英文。宿主与自研插件共用此范围。

目标产品名、包名和运行名统一为 `spark233`，新的 Electron appId 采用 `com.spark233.desktop`。配置和 Chromium profile 使用 `appData/spark233` 下的独立目录，默认便签正文位于用户文档目录下的 `spark233`。服务、通信端点、环境变量、安装包和快捷方式使用新的 spark233 命名空间；具体插件 npm scope 在发布前核对可用性和账号归属。当前源码中的花笺名称、路径和标识是待替换现状，不提供旧名称别名或自动发现迁移。

首次正常启动显示启动器与简短引导，不自动创建空便签。后续正常启动恢复本产品已保存的便签布局并驻留托盘，启动器等待快捷键或托盘呼出；显式命令启动按命令行为处理。启动器由搜索框、分组候选、插件工作区与快捷键提示组成，便签管理页是其中一个工作区。启动器、截图和新建便签是独立动作，快捷键统一设置、检测冲突，不以新建便签作为默认主入口。

七个官方业务插件默认预装并启用，剪贴板启动即记录；启用不等于每个插件都创建常驻窗口或立即加载模型。OCR 按任务启动，应用搜索建立应用索引，文件服务随安装流程默认集成并请求系统授权；拒绝授权时显示该能力未就绪及重试入口，宿主其他能力继续使用。基础截图、OCR 和词典首装即可离线使用，AI 未配置时提供配置入口且本地词典继续工作。用户后续停用状态跨重启和更新保留。

## 3. 产品交互与前端模型

### 3.1 Rubick 式关键词匹配入口

快捷键呼出启动器后聚焦输入框。宿主根据启用插件的关键词、别名、拼音、文本规则与上下文匹配入口和动作；用户执行后进入插件工作区或直接完成操作。

| 输入或上下文       | 默认结果                                         | 后续交互                          |
| ------------------ | ------------------------------------------------ | --------------------------------- |
| 英文单词及词形     | 本地释义、查词与翻译动作，同时保留同名应用和命令 | 展开词条或主动选择 AI 解释        |
| 句子或段落         | AI 翻译、保存便签等动作                          | 执行动作后再请求模型              |
| 文件搜索关键词     | 文件与正文搜索入口                               | 进入模式后，将输入交给 Pulse 来源 |
| 应用名、拼音或缩写 | 应用与插件命令                                   | 启动应用或进入插件                |
| 剪贴板关键词       | 历史入口                                         | 在历史工作区继续筛选与搜索        |
| 图片或文件上下文   | 能处理该类型的插件动作                           | OCR、保存便签、打开文件等         |

关键词和规则由插件合同注册，宿主统一匹配，不为每个插件编写独立硬编码分支。精确命令、上下文和用户选择需要可解释，不能让单词自动识别吞掉同名应用入口。

默认界面优先呈现应用、命令、智能动作和即时本地查词，不在每次输入时强制扫描或混合所有正文。文件、便签、剪贴板分别可进入专门模式；统一搜索来源合同保留，后续可组合为“搜索全部”动作。

空查询显示固定命令、常用入口和最近使用项。支持键盘选择、回车执行、返回上一级与取消。进入插件后提供明确模式标识和输入提示；Esc 处理局部弹层后才返回或关闭启动器。

### 3.2 呈现与焦点

| 方式              | 典型用途                            | 生命周期                                   |
| ----------------- | ----------------------------------- | ------------------------------------------ |
| 结果中直接执行    | 启动应用、复制历史、新建便签        | 操作完成即可结束                           |
| 启动器内工作区    | 文件搜索、词典翻译、剪贴板          | 进入、返回、恢复、销毁均明确               |
| Electron 独立窗口 | 桌面便签、完整管理页、必要 OCR 结果 | 宿主管理身份、焦点、保存与关闭             |
| 外部原生工作面    | ScreenCapture 选区与标注            | 截图插件管理进程和会话，宿主协调前台与结果 |
| 后台运行          | 记录、提醒、OCR、索引               | 可独立于页面启停                           |

内部窗口切换、菜单、对话框和原生截图过程不能误触发失焦收起。关闭启动器不等于关闭便签或停用后台；退出应用仍等待保存。

模式工具栏按钮保留 Enter/Space 的原生激活语义，阻止这两个按键冒泡到 cmdk 的结果选择逻辑；返回模式后清空查询和结果并恢复输入焦点，Esc 复用相同取消路径。查询身份同时失效，迟到结果不得重新填回已退出的模式。

Windows 便签置顶与胶囊使用 Electron 公开的 `pop-up-menu` 层级，避免默认 `floating` 在主任务栏后排时丢失实际置顶；其他平台保持 `floating`。该 Windows 层级允许高于任务栏，但已有全屏避让仍优先，逻辑置顶偏好不因临时降级丢失；显示、移动和缩放后按当前几何重新应用。实际打包与尚未覆盖的物理全屏边界见[置顶续修](evidence/spark233-native-pin-repair.md)。

### 3.3 React + shadcn/ui

宿主、设置、插件管理及自研 Web 插件界面采用 React、TypeScript、Vite、Tailwind CSS 和 shadcn/ui。shadcn/ui 组件作为项目源码管理，沿用语义主题和可访问性规则，组件负责交互呈现，插件匹配与搜索调度属于业务服务。

启动器可组合 Command、分组列表与快捷键提示；管理页使用 Card、Table、Tabs 和表单；翻译、剪贴板可使用 Resizable、ScrollArea、ContextMenu。实际组件选择、基础库和视觉方案在实现时核对当前官方合同。

ScreenCapture 的截图与标注窗口保持原生实现，不以重写为 React 作为接入前提。第三方 Web 插件不强制绑定 React，但需遵守 SDK、能力和生命周期合同。

- 宿主发布主题标识与变化通知，独立 Web 页面加载同一套主题定义；浅色、深色、跟随系统覆盖启动器、独立窗口和官方插件。
- 官方插件复用版本化 UI 包，包含 shadcn 基础组件与通用业务组件；UI 包记录自身版本、主题协议和 SDK 兼容范围，不依赖宿主内部路径或全局 CSS 偶然生效。

- 跨窗口弹层、滚动条、焦点、快捷键与长文本遵循统一规则；中文输入法组合期间不误执行命令，列表键盘操作与可见焦点完整。
- 界面完成后运行 Vercel 指南检查，并对浅色、深色、中文长文本、空数据、错误与缩放场景保存截图；Web 专用规则按 Electron 的实际场景适用。

当前共享包为 `@spark233/ui` 0.3.0，兼容 SDK `>=0.2.0 <0.4.0`、宿主 API `^1.1.0` 与主题协议 `^1.0.0`。框架无关的主题 CSS/应用函数保持独立入口；可选 React 入口提供 Button、Alert、Badge、Card、Input、Textarea 与 Spinner 家族及预编译语义 CSS。组件唯一源码位于 `packages/ui/src/components/`，桌面原组件路径只保留重导出；构建生成包内 JavaScript、类型声明和样式，发布物不引用宿主源码路径，React 与现有基础库通过 peer 提供。官方剪贴板工作区通过包入口消费，正常 renderer 构建及官方归档记录实际 UI 包版本、兼容范围和入口散列；字体 v1 合同单独版本化。更多业务组件沿用同一包复用规则，不为满足条目数量新造控件。

交互原语统一采用 shadcn Base Nova 与 Base UI：共享 Button、Input 和 Badge，以及桌面的对话框、菜单、复选框、分隔线和 Toast。Command 沿用官方 Base 集合的 cmdk 组合方式。瞬时操作反馈由统一 Toast 管理，在当前窗口顶部居中展示，合并重复提示并保留输入焦点；加载错误、任务进度与未保存状态继续留在对应内容区。迁移和验证记录见 [Base UI 与通知](evidence/toast-base-ui-2026-10-30.md)。

## 4. 宿主、插件与进程边界

### 4.1 职责划分

| 模块           | 拥有的职责                                       | 与其他模块的协作                         |
| -------------- | ------------------------------------------------ | ---------------------------------------- |
| 宿主核心       | 单实例、启动退出、配置、托盘、主题、语言         | 编排插件和平台资源                       |
| 插件管理       | npm 包发现安装、兼容检查、启停、依赖、更新和回滚 | 登记代码、命令、后台、窗口与原生资源归属 |
| 入口与动作路由 | 关键词和内容匹配、模式切换、输入上下文、执行路由 | 消费插件注册规则和能力                   |
| 搜索协调       | 模式内来源调度、取消、排序、分页与结果动作       | 汇总启用来源，不绑定具体业务格式         |
| 窗口与进程管理 | Electron 窗口、外部原生会话、焦点、保存关闭      | 插件持有页面或业务状态                   |
| 平台服务       | 文件授权、剪贴板、通知、前台与系统调用桥接       | 按实际调用者与能力使用资源               |
| 业务插件       | 便签、截图、OCR、翻译、历史与搜索                | 通过 SDK 协作，独立持有业务和数据        |

宿主不依赖便签路径、词典结构、历史表或 Pulse 索引格式。系统调用桥接可共用，业务引擎与原生程序随所属插件包分发。

输入框和列表属于宿主，具体命令、模式与搜索来源属于插件。停用某个搜索插件不影响启动器和其他已启用模式。

### 4.2 一期插件划分

| 插件           | 业务范围                                             | 停用后的行为                                   |
| -------------- | ---------------------------------------------------- | ---------------------------------------------- |
| 便签           | 列表、编辑、桌面窗口、胶囊、提醒、搜索               | 保存后释放窗口与调度，撤下入口和结果，保留数据 |
| 截图           | ScreenCapture 选区、常用标注、复制保存、OCR 动作桥接 | 注销快捷键，安全结束原生会话与进程             |
| OCR            | 图像识别、选字复制、模型与后端管理                   | 取消任务、释放后端，基础截图仍可用             |
| 翻译与词典     | 即时查词、AI 翻译、结果、缓存                        | 停止请求并撤下匹配规则，保留词库与配置         |
| 剪贴板         | QcClip 式历史、收藏标签、素材、搜索与快捷回贴        | 停止监听与后台，撤下入口和结果，保留数据       |
| 应用搜索       | 应用索引、匹配、启动                                 | 撤下来源并停止任务                             |
| 文件与正文搜索 | Pulse NTFS 文件名索引、Instant 正文、状态重建        | 撤下模式和来源，停止所属后台，保留索引         |

OCR 对截图是可选运行能力，取字是一期必须交付的功能。用户主动关闭 OCR 时截图不强制重新启用它。词典和 AI 为同一插件，大型资源可独立版本化但需声明兼容关系。

### 4.3 进程与加载模型

- Electron 主进程编排资源，扫描、推理、全文解析等重任务放入受管理后台。
- 启动器与 Web 插件使用独立构建入口，页面从各自插件安装目录加载，不静态并入宿主主包。
- WebContents 由宿主管理；独立视图不等于固定独占一个 OS 进程。
- ScreenCapture 是 npm 插件包中的外部原生程序，截图插件通过受控接口启动，登记会话、窗口、资源与退出状态。
- ImageReader 及其模型和后台由 OCR 插件持有，禁止另留不可停用的重复识别后台。
- 原生模块按需放入可重启的可信后台，以便切换插件版本。
- Pulse 文件名服务与用户态正文读取区分权限，通过插件适配层调用。

关闭页面和停用插件分别处理。后台异常、原生工具退出和单插件崩溃不应阻止其他命令使用。不得让卸载后的进程或模型长期驻留。

### 4.4 信任边界

普通外部 Web 插件通过受限 SDK 使用能力，保持 sandbox、contextIsolation 和 webSecurity，关闭页面 Node 集成。预加载由宿主管理。

实际 WebContents、frame 与运行实例决定调用身份；检查能力、参数、资源归属、版本和启用状态，不信任页面提交的插件 ID。隔离来源与存储，限制导航、新窗口和文件访问。

完整 Node 后台、原生模块与 exe 属于可信扩展，独立进程只提供故障隔离，不等于权限沙箱。插件来自 npm 并不自动获得可信原生执行权限。

官方原生插件随产品预置信任；第三方 Web 插件按受限能力授权。第三方完整 Node 后台和原生程序在安装时展示来源、精确版本及申请能力，由用户显式信任后才允许执行；更新新增能力时重新确认。registry 来源和 tarball 完整性校验不能代替信任授权。

原生程序只能按已校验清单和受控参数启动，不接受搜索结果中的任意 shell 命令。复用 Pulse 时保留调用者可见性过滤，不因服务提权扩大文件访问范围。

## 5. 插件合同与生命周期

### 5.1 npm 包清单与 SDK

插件发布为 npm 包，标准 package.json 表达包名、版本、分发文件和许可证，自有插件字段表达宿主合同。具体字段名在实现时确定，不将当前设计视为已存在的 API。

| 合同 | 内容                                                      |
| ---- | --------------------------------------------------------- |
| 身份 | npm 包名、稳定插件 ID、独立版本、名称、图标               |
| 兼容 | 宿主 API、最低宿主、平台、CPU 架构、后台协议              |
| 入口 | 预构建页面、后台、原生程序及资源                          |
| 匹配 | 命令 ID、关键词、别名、拼音、文本规则、优先级与上下文类型 |
| 模式 | 文件搜索、剪贴板等工作区身份、提示词、返回语义            |
| 搜索 | 来源、可索引内容、过滤与结果动作                          |
| 权限 | 后台、剪贴板、原生程序、文件与网络等能力                  |
| 依赖 | 必需插件、可选能力和兼容范围                              |
| 数据 | 数据版本、迁移、备份和卸载策略                            |
| 更新 | registry 来源、渠道、完整性、资源版本与重启范围           |

规则匹配只产生入口或本地结果；昂贵任务与 AI 请求在用户执行动作后触发。相同输入可产生多个候选，保持可解释的排序和手动选择。

插件 ID 与 npm 包名的关系在清单中固定，不能由任意包冒用已安装插件身份。API、包、数据、词库与模型版本分别管理，安装前检查兼容。

宿主 API 1.1.0 支持命令的 `requiresPlugins`：其中每个插件 ID 必须已出现在所属插件的必需或可选依赖中，兼容范围沿用该依赖声明。所需插件缺失、停用、出错或版本不兼容时，该命令从启动器和管理页撤下，实际派发也在启动后台前拒绝旧调用；其余命令继续工作，不自动启用依赖。截图包 0.1.1 的取字命令据此依赖 OCR，基础截图不依赖 OCR。本轮 SDK npm 包 0.3.0、宿主 API 1.2.0 与主题协议 1.0.0 分别版本化；requiresPlugins 的既有 API 1.1 合同继续兼容。

宿主提供 SDK 和类型定义，内置插件与外部插件遵守同一生命周期。npm 分发不代表兼容任意 Node 项目，宿主不承担任意依赖树的自动安装和构建。

### 5.2 生命周期语义

| 动作     | 必须发生的行为                                                 |
| -------- | -------------------------------------------------------------- |
| 发现     | 只读取并校验清单，不执行插件代码                               |
| 安装     | 校验包和兼容性，建立代码、能力及数据归属                       |
| 启用     | 注册命令和搜索来源，按策略启动后台                             |
| 激活     | 携带命令或上下文进入插件，按需加载页面                         |
| 关闭界面 | 保存必要状态，释放或保留视图，后台按策略继续                   |
| 停用     | 注销命令、快捷键、事件和搜索来源，取消任务，关闭窗口并释放后台 |
| 更新     | 保存并停止旧版本，切换产物，检查新版，失败执行匹配回滚         |
| 卸载     | 先停用，再移除代码；数据清理由用户选择                         |
| 应用退出 | 等待保存和后台落盘，失败按可恢复策略处理                       |

仅隐藏入口而后台继续工作不算停用成功。有未保存内容时，停用、更新和退出先进行保存确认；失败则取消操作，保留旧运行实例和可恢复内容。

后台不要求始终创建隐藏页面，每个常驻进程都应有明确用途。任务结果携带查询或运行实例身份，停用或更新后到达的旧结果不得继续修改新实例界面或数据。

安装、启停、更新和卸载的持久化事务仍串行，但无关插件的活动命令、查询及冷启动不等待整段事务。每个插件的启动过程按身份去重；目标或必需提供者处于变更时拒绝旧调用，不排队到新版实例执行。备份、恢复及退出采用全局维护屏障，先阻止新业务并等待已进入的启动完成，再保存和释放。状态恢复后通知各工作区，旧 owner 的崩溃通知不能写入替换后的安装记录。

### 5.3 插件之间的依赖与数据传递

跨插件调用通过宿主能力路由。截图只在 OCR 能力可用时提供识别动作，关闭 OCR 后截图和标注继续可用。OCR 结果可以送到翻译或便签，剪贴板条目也可转交这些插件。

关闭目标插件时，入口显示不可用及原因，宿主不擅自启用它。必需依赖缺失时拒绝相应插件启用并说明影响；可选依赖缺失仅撤下相关动作。依赖版本更新前检查受影响插件，避免更新后才发现合同不兼容。

共享资源按使用者登记并释放，不能因停用一个消费者误停其他插件正在使用的资源。停用 OCR 本身时，需要终止它提供的识别任务并通知消费者。

图片、文字、文件引用通过明确的资源句柄或受校验数据传递，避免直接读写其他插件私有目录。临时资源转交后由接收方确认持久化，完成前不得删除。

## 6. npm 分发、独立更新与数据归属

### 6.1 发布与包内容

已确认使用 npm registry 分发，取消 Cloudflare Workers、R2、D1 及自建网页发布后台，不自建 registry。发布者用 npm CLI 或 CI 发布，npm 页面查看包和版本；桌面端提供用户插件管理。

每个业务插件有独立 npm 包、版本、构建产物和安装目录，预装只是初始分发方式，之后可单独升级。包可包含编译后的 Web 资源、后台、ScreenCapture.exe、必要原生文件、清单和许可证。

发布前完成构建，运行依赖打包或以明确的平台资源包表达，不依赖用户机器编译或安装后下载不明产物。模型和词库可作为单独资源包，但版本、平台、授权与兼容关系需要明确。

稳定版、测试版使用 latest、next 等 dist-tag；tag 是渠道指针，安装记录固定到确切版本与完整性信息。同名同版本不作为覆盖更新方式，发布新产物使用新版本。

发布凭据只存在于开发或 CI 环境，不放进桌面客户端。初期按明确的一方插件目录提供发现与更新，不把“npm registry”扩大成自动发现全部 npm 包的插件市场。

### 6.2 客户端安装

客户端查询 registry 元数据，选择满足宿主 API、平台、渠道与依赖范围的版本，下载对应 tarball，校验 dist.integrity 等完整性信息，解包并检查自有插件清单。

用户不需要安装 Node/npm。优先使用 npm 生态成熟的元数据与包获取组件，不在用户机器执行 npm install、插件安装脚本或临时构建。版本选择不是无条件取 latest。

支持输入明确包来源、从产品插件目录选择、导入本地 npm .tgz，以及开发目录。离线包使用同样校验规则；需要注册 Windows 服务的可信插件通过宿主受控安装流程提权。

校验包含包与插件身份、入口、完整性、宿主与依赖、架构、体积和文件数。解包拒绝绝对路径、路径穿越及链接逃逸。临时目录验证成功后才切换生效。

### 6.3 独立更新与回滚

流程为检查新版本、下载验证、检查依赖、保存并停止旧实例、备份数据、切换代码、启动检查和提交版本。更新保持用户启停状态，关闭中的插件不能因更新自行启动。

客户端自动检查并提示更新，由用户确认安装，默认使用稳定渠道；测试渠道由用户主动开启。活动编辑、截图标注或其他会话按保存与关闭规则处理后才能切换，需要管理员授权或宿主重启时提前说明。

更新截图插件只替换所属 npm 包与原生资源，不重新发布便签、剪贴板或整个宿主。ScreenCapture 有活动窗口或未保存标注时先完成安全结束，不能直接覆盖运行中的 exe。

无法卸载的原生模块通过重启所属后台切换，确实需要宿主重启时提前说明。数据迁移后回滚必须恢复匹配的数据备份，不能只保留旧代码。

当前显式迁移合同为清单的 `migration.entry`：独立受信任 Node 模块在普通后台 factory 之前执行，确认目标数据版本且进程退出后才启动新版。已提交的 npm 包身份、数据版本和插件版本由宿主记录；保留数据卸载后仍保留绑定，未知版本和未经支持的降级明确拒绝。停用插件更新只做初始化检查，不启用业务资源。具体接口见 [SDK 说明](../packages/sdk/README.md)，真实迁移与匹配恢复证据见[管理器记录](evidence/spark233-plugin-manager.md)。

Pulse 服务安装、升级与卸载可能需要管理员授权，日常宿主保持普通权限。防止新旧服务同时写一个索引。插件更新还需处理残留进程、未完成事务、锁和协议不匹配。

更新各阶段记录可恢复状态，覆盖下载、备份、迁移、切换与提交之间的崩溃或断电。未提交新版前阻止新旧实例并行写入；若新版已产生用户数据，回滚先保护该增量，再执行匹配的数据恢复或进入可诊断恢复状态，不能以覆盖备份丢弃新增内容。备份导出需要协调数据库与外置资源写入，保证一致快照。

恢复确认绑定预览时已经验证的整个 manifest 指纹，预期身份只保存在宿主 opaque selection 中。恢复必须在保存停机或写入前比较身份，并固定使用同一 manifest 校验和 staging；路径被另一份完整有效备份替换时也须重新预览。开始重新选择、选择失败或取消时撤销旧确认卡，身份变化使原选择失效；保存拒绝等可重试错误继续保留当前选择。

外置数据根由宿主按插件身份登记，备份服务只保存不透明数据域，不读取便签等业务格式；宿主配置位置由宿主自己的适配器读取及重绑。快照与恢复 journal 的 schema 2 使用通用插件域，旧 schema 1 通过显式授权的别名读取，预览指纹仍绑定原清单。中断 journal 不能自行扩张恢复目录，也不能以默认根覆盖已持久化的配置身份。

### 6.4 数据归属

| 数据域   | 内容                                        | 恢复原则                   |
| -------- | ------------------------------------------- | -------------------------- |
| 宿主配置 | 主题、快捷键、插件状态、registry 与渠道配置 | 独立备份迁移               |
| 插件代码 | npm 精确版本、页面、后台、原生产物          | 可替换，不混入用户数据     |
| 插件数据 | 便签、剪贴板历史、收藏、翻译配置、业务状态  | 按插件保留导出             |
| 大型资源 | OCR 模型、词库与平台资源包                  | 独立版本校验，绑定兼容关系 |
| 索引     | 文件、正文、插件内容的派生数据              | 可重建，不作为唯一正文     |
| 缓存     | 图标、缩略图、临时图片、可清理译文          | 按所有者清理，保留原始数据 |

ScreenCapture 的配置和临时数据应放在插件专属数据域；若采用工具便携配置模式，需要避免更新代码目录时覆盖设置，不写入不可变包版本目录。

迁移保留的旧根、失败复制、导出快照及恢复中间目录也是私有数据。宿主在写入前持久登记搜索排除并等待在途查询取消；请求、结果发布和旧选择动作均读取最新排除。此账本位于可恢复宿主目录之外，只增加排除，不能充当文件授权或恢复目标白名单。恢复旧配置不得重新暴露这些副本。

多窗口设置写入只提交本次修改的字段，在宿主最新配置上合并；不得用页面持有的全量旧快照覆盖其他窗口的新值。数据位置仍只能经过显式迁移事务修改。

卸载默认保留用户数据，明确删除时同步清除索引和缓存。停止服务或共享后台前检查资源归属与消费者，不能误停其他合法使用者。

### 6.5 完整离线首装与体积预算

标准 Windows x64 安装包预装七个业务插件、ScreenCapture、ImageReader 内嵌模型和 ECDICT 基础约 76 万词条词库。词库构建为仅包含所需字段与索引的运行数据库；用户无需安装 Node、Python 或手动下载模型。完整版词库作为后续可选资源，不扩大一期首装要求。插件与资源仍独立版本化，首装预置不改变其独立更新合同。

以下为 2026-10-24 设计阶段的体积核对，MiB 按 1,048,576 字节计算。七插件、基础运行词库与 Windows 完整包现已构建；当前实测值以[分发记录](evidence/spark233-packaging.md)为准，下表保留作预算对照：

| 组成                    | 安装占用       | 证据性质                                                |
| ----------------------- | -------------- | ------------------------------------------------------- |
| Electron 45 Windows x64 | 356.77 MiB     | 当前本地运行时实测                                      |
| 当前前端及主进程产物    | 22.13 MiB      | 本地 dist 与 dist-electron 实测，含字体                 |
| ScreenCapture 2.5.15    | 1.85 MiB       | 官方发布物 1,943,040 字节                               |
| ImageReader 1.0.2       | 24.69 MiB      | 官方发布物 25,891,840 字节，已含两个 OCR 模型           |
| Pulse 独立后端          | 预留 10–25 MiB | 完整 portable 解压为 23.84 MiB，独立产物尚未构建        |
| ECDICT 基础运行词库     | 估 70–140 MiB  | 基础 CSV 实长 66,009,548 字节；数据库与索引尚未转换实测 |

计入新增插件代码、依赖与余量后，标准离线包暂按下载 170–220 MiB、安装占用 500–650 MiB 规划。这是基于当前产物的工程估算，不能写成已构建 spark233 安装包的实测值。现有宿主安装包 120.91 MiB 仅来自 2026-10-23 的构建记录，当前没有该安装包现场复测。

ECDICT 现成完整版 SQLite 压缩包为 216,765,132 字节（206.72 MiB），内部数据库为 851,288,064 字节（811.85 MiB），与基础约 76 万词条方案不是同一档位。直接预装该完整版时整体约需下载 350–400 MiB、安装 1.2–1.35 GiB。剪贴板、便签、索引、缓存与回滚副本另计使用增量，安装空闲空间要求在实包验证时确定。

## 7. 模式内搜索与统一来源合同

### 7.1 搜索来源与插件归属

| 来源                 | 归属与实现                                               | 主要结果动作                 |
| -------------------- | -------------------------------------------------------- | ---------------------------- |
| 插件命令             | 宿主汇总启用插件注册的命令                               | 执行、进入工作区             |
| Windows 应用         | 应用搜索插件，开始菜单、注册信息、Store 应用与自定义入口 | 启动、打开所在位置           |
| 文件和目录           | 文件与正文搜索插件，Pulse 原生索引后端                   | 打开、定位、复制路径         |
| 便签                 | 便签插件提供内容与变更                                   | 打开、定位正文、贴到桌面     |
| 文本、Markdown、代码 | 文件与正文搜索插件，Pulse Instant 按需正文查询           | 预览命中、打开文件、定位行   |
| 剪贴板               | 剪贴板插件，历史与收藏索引                               | 复制、粘贴、翻译、发送便签   |
| 单词词典             | 翻译插件，本地词库                                       | 查词、查看词形、进入 AI 解释 |

上述是各模式可用的来源，不要求默认输入框同时混合全部结果。入口先执行第 3 节的命令与内容匹配，进入工作区后使用当前模式注册的来源与过滤条件。

搜索来源可以返回实时结果，也可以使用宿主提供的派生索引能力。停用插件后立即撤下它的来源；索引后台属于相关插件，而非不可关闭的宿主业务。普通 Web 插件不得借搜索索引取得其他插件正文读取权限。

### 7.2 查询与结果合同

查询包含当前模式、查询文本、来源过滤、上下文、结果上限和取消信号。每次输入变化产生新的查询身份，旧查询结果不再进入当前列表；后台进程和外部搜索子进程也应尽可能真正取消。

结果至少包含稳定身份、来源、类型、标题、可选路径、命中片段、可选预览和可执行动作。动作使用宿主已经注册的命令与受校验参数，不能把搜索结果中的字符串直接当作 shell 命令执行。

快速来源先返回，较慢来源渐进补充。合并结果时保留当前键盘选中项的身份，避免补充结果导致用户回车执行了另一项。分别限制来源配额和总结果数，提供继续查看或分页。

名称与路径的排序初始使用精确命中、前缀、拼音和缩写、模糊匹配等规则；正文来源结合词项命中、标题、路径和使用历史。各来源的原始相关度不能直接假定可比较，应由宿主归一或分组呈现。

同一文件被多个索引来源返回时去重；便签目录中的 Markdown 优先呈现为便签结果，避免重复的通用文件正文结果。用户主动选择文件筛选时仍可查看文件结果。

### 7.3 Windows 应用搜索

索引用户与系统开始菜单快捷方式，并补充注册应用、Store 应用和手动配置入口。保留快捷方式的参数和工作目录等启动语义，避免只取目标 exe 导致应用行为变化。

缓存图标和名称，生成拼音与缩写检索字段，排除明显卸载入口。变更监听结合定期轻量校准，失效入口在执行前检查并允许刷新。

### 7.4 Pulse 文件名与路径后端

采用基于 Pulse 原生索引后端的路线。已核对的源码包含索引客户端、命名管道协议、MFT 枚举、USN 变化跟踪、拼音匹配、查询分页与调用者权限过滤。

文件名索引使用原生专用索引结构；不能将 Pulse 的整个文件搜索实现描述为 SQLite 表。SQLite 和自定义 FTS5 主要属于其内容索引路径。

实现前固定上游版本，整理构建依赖，并在直接协议适配与薄原生桥接之间选择可维护方案。Pulse 当前客户端带有窗口消息等应用集成，复制 src/index 目录并不等于独立可构建 SDK。保留必要的安全、持久化、查询取消与恢复逻辑。

安装索引服务时明确请求管理员授权，之后宿主普通权限查询。采用本项目独立服务名、通信端点、锁和数据目录，避免与已安装 Pulse 冲突。服务按调用者权限过滤结果，不能把高权限索引当作任意文件枚举接口。

已确认沿用 Pulse 当前默认：安装器默认集成并启用文件名服务，自动纳入在线固定 NTFS 卷和移动 NTFS 卷，允许在设置中排除卷及路径；不增加首次必须逐卷选择的流程。默认开启 Windows、临时目录、旧系统残留和 node_modules 等排除。网络盘与非 NTFS 卷不进入这套默认 MFT 索引，不把尚未验证的覆盖宣称为已支持。

首次建索引、更新、暂停、服务不可用、重建与实际覆盖磁盘应有明确状态。NTFS、非 NTFS、网络盘、可移动盘的能力需分别验证。未安装或未启动服务时解释当前不可用范围，其他来源继续工作。

Everything 不作为一期默认依赖，避免同时维护两套全盘索引生命周期。

### 7.5 Instant 正文查询与派生索引

已确认沿用 Pulse 当前 Instant 模式：正文范围跟随文件名索引已启用的卷及排除路径，查询时按需读取，启动时不进行全盘正文预读或建立完整正文库。用户可缩小到指定目录并调整排除设置；指定目录是可选筛选，不再作为首次使用前置条件。

Pulse 的文件名索引、Instant 正文查询与可持久化内容索引是不同路径，应分别核对协议及依赖。自定义 FTS5 GramTokenizer 属于其内容索引路径，不能将验证 tokenizer 等同于跑通 Instant。首版使用词法检索，不引入向量模型；先验证 Instant 的独立构建、调用、取消、分页与中文代码召回，不为复用上游能力额外引入常驻全文扫描任务。

一期正文格式覆盖文本、Markdown 和代码；PDF、Office 仍在范围外。沿用默认卷和系统排除规则，提供类型、大小、隐藏文件及用户排除设置。Pulse 默认文本单文件上限为 64 MiB，该值在目标后端适配时验证；上游文档解析 512 MiB 上限不构成一期承诺。

正文读取和查询放在受管理的用户态后台，控制批次和并发，保持当前用户权限，不因文件名服务提权扩大正文读取范围。处理二进制、无法解码、超大文件、重解析点、离线文件及云占位，不能为查询擅自下载全部云文件。

查询结果及可选缓存携带文档身份和文件版本，文件改名、删除、移动、卷离线或范围撤销后不得返回陈旧正文。若采用持久化派生索引，再实现对应变更补偿和重建合同。便签与剪贴板通过自己的内容合同接入，不扫描其私有存储制造重复结果。

固定样例验证中文短词、连续中文、英文混排、路径和代码符号的召回、排序及取消成本。ripgrep 仅用于明确指定的补充或诊断，默认不使用全盘递归扫描代替 Pulse 后端。

### 7.6 搜索数据的生命周期

插件通过稳定内容 ID 提交新增、更新与删除，停用或卸载时从搜索中撤下该插件结果。取消某个目录的索引授权后，清除相应正文、摘要和预览缓存。

索引是可能含正文片段的本地敏感数据，应跟随明确的数据目录策略，不自动上传或同步。剪贴板等来源需跟随其保留、删除和隐私设置，不能在历史删除后仍通过全局索引找回。

索引损坏时保留插件原始数据，重建派生索引。索引版本升级、重建和后台异常应有进度与可诊断状态，界面继续提供可用来源。

## 8. 便签作为第一个插件

便签插件拥有便签列表、编辑和预览、分类、图片、桌面便签、每张便签的显示偏好与提醒业务。宿主负责窗口控制、系统通知、全局快捷键注册和退出协调。

便签继续采用 Markdown 正文和独立附件文件，复用当前编辑、分类、提醒与桌面布局能力。代码拆分时以隔离样本回归正文、ID、图片相对路径和保存行为，不为了插件化强制将正文转换为数据库；这项工程回归不代表支持旧版花笺配置和数据自动迁移。

当前 NoteStore 混合管理的全局设置逐步拆为宿主配置与便签设置。启动器呼出、便签新建、便签显隐是不同动作，快捷键在 spark233 设置中统一注册并处理冲突，不承担旧版设置兼容。

胶囊交互先保持现有行为。宿主可以管理窗口与显示资源，便签插件提供标题、预览和业务动作；只有第二个插件确实需要相同机制时，再抽取通用胶囊合同。

便签搜索结果的“打开”与“贴到桌面”分别定义。定位正文遵循当前保存与刷新约束，不覆盖正在输入的内容；对未保存内容是否搜索，首版默认以已提交的正文为准，并明确说明。

工程验证先备份并使用隔离数据副本。产品名、appId、默认目录与安装身份按第 1.3 节整体换新，不探测或自动迁移旧花笺数据；原有真实文件与未提交工作保留。

## 9. 剪贴板插件设计约束

### 9.1 参考范围与平台访问

已确认以 [QcClip](https://github.com/mosheng1/QcClip) 的逻辑与业务功能为参考，审阅提交为 `be6d2deea37753cdfe570c9009571ac16046bf01`。它是 Rust/GPUI 独立应用，未发现可直接调用的公共 Electron 插件接口；参考功能和数据规则不等于直接嵌入整个应用。代码复用保留 Apache-2.0 所要求的归属和声明，附带第三方代码另外核对。

平台访问优先验证 @crosscopy/clipboard，包括监听、原始多格式读写、文件复制和回贴保真；该库能否覆盖 QcClip 参考功能需要实测，不能只凭包说明判定完成。若存在缺口，在前置技术验证中说明证据与适配成本。系统访问通过宿主平台合同，库和后台具有明确插件归属与更新边界。

插件默认启用并从启动起记录；关闭界面继续记录，暂停停止捕获，停用则停止订阅并释放资源。验证系统变更通知路径，避免固定频率反复读取和编码大图。宿主统一管理托盘、自启、主题、快捷键、插件更新、数据位置与备份入口。

### 9.2 多格式数据、去重与回贴

一期记录文本、HTML、RTF、图片和文件路径，保存同一次复制的多个原始格式并生成可搜索预览。采用明确的格式白名单，不假设所有系统自定义格式均可安全保留和恢复。自写入与回放标记或抑制重复。

参考 QcClip 的内容哈希与文本合并规则：精确重复更新最近时间、次数和来源；同文本合并需要校验完整内容与格式，图片、文件和嵌入媒体不得因预览相同而丢失。元数据与小内容使用独立数据库，大资源外置并记录内容身份、引用与回收关系；删除历史不能误删收藏或图库仍引用的资源。

文件历史保存 CF_HDROP 等实际文件复制格式和路径引用，不备份原文件，不用路径文本冒充文件复制。原文件改名、删除或不可访问时显示失效情况，粘贴前重新检查。主动导入图库则复制资源到本插件数据域，与文件历史引用语义区分。

“复制”与“粘贴回原应用”分别定义。回贴恢复前台窗口与焦点，支持保留格式、纯文本、图片按文件粘贴及快捷选取；权限受限时反馈失败并保留已复制内容。批量合并文字、图文或文件纳入一期，文件与文本混合组合不作为承诺。

### 9.3 历史、收藏、素材与界面

一期包含历史与独立收藏关系、分别置顶及排序、多标签、备注、文本编辑与恢复原内容。搜索覆盖正文预览、各格式可检索文本、备注和来源应用，支持类型过滤及预览；图片不会仅因进入历史就自动获得 OCR 全文索引。

图库、表情、符号、最近使用、图库分组和批量合并均纳入一期。启动器内提供完整剪贴板工作区，便捷粘贴小窗作为快速入口，提供键盘选取、数字或 F 键快速粘贴设置及适用的贴边和鼠标附近呼出方式。所有入口共用同一份数据、能力和宿主生命周期；全局快捷键显式配置并处理冲突。

剪贴板条目可主动发送 OCR、翻译和便签，不随捕获自动请求 AI。导入导出和数据目录调整纳入宿主统一备份恢复合同，数据库与外置资源需要一致快照，不能在未协调写入时声称备份完整。

### 9.4 保留、待清理与排除

已确认沿用 QcClip 默认：不限历史保留天数和条数，默认不在启动时自动清理，也不使用此前建议的 7 天、1,000 条或 256 MiB 自动淘汰。提供占用统计、可配置保留范围、待清理列表、主动清理、暂停和应用排除。

保留范围控制普通历史的可见范围；超限内容进入待清理状态，尚未删除时调整设置可恢复显示。置顶免于普通历史范围淘汰，收藏使用独立关系。常规搜索遵循当前可见范围，不绕过待清理状态；确认清理后同步删除对应搜索记录和不再被任何有效条目引用的资源。插件停用时从宿主撤下其结果。

尊重 Windows 的 `ExcludeClipboardContentFromMonitorProcessing` 和 `CanIncludeInClipboardHistory=0` 等敏感标记，并支持用户应用排除。应用排除列表默认空；这些机制不构成自动识别所有密码的承诺。

## 10. ScreenCapture 截图、取字与翻译插件

### 10.1 已确定的截图路线

采用 xland/ScreenCapture，由截图 npm 包携带固定版本原生程序及资源，Electron 宿主通过受控进程调用接入。无需用户手动另装工具，不移植 eSearch 整套截图页面。

当前发布版 2.5.15 是实施验证候选，正式发布前固定下载产物、哈希与依赖。原生工具保留选区与标注工作面，插件配置、管理与必要自研结果界面使用 React + shadcn/ui。

截图插件负责快捷键、原生会话、前台隐藏恢复、结果接收与版本生命周期；宿主登记调用权限、资源和所属插件。OCR 识别及结果归 OCR 插件，翻译与便签通过能力路由接收数据。

### 10.2 微信截图常用功能的一期范围

| 能力     | 必需验收行为                                      |
| -------- | ------------------------------------------------- |
| 选区     | 框选、窗口识别、调整位置尺寸、取消                |
| 标注     | 矩形、椭圆、箭头、画笔、文字、马赛克              |
| 编辑     | 撤销、重做，保留选定版本可用的标注编辑            |
| 输出     | 复制图片、保存文件，取消不改变原剪贴板            |
| 直接取字 | 当前选区点击提取文字，支持全部复制与部分选字复制  |
| 联动     | 识别文本送到词典、AI 或便签，图片可保存为便签附件 |

“对齐微信”指上表明确范围，不承诺微信每个版本的所有按钮与内部实现。无需手动先保存图片、打开 OCR 插件再导入，也不能取字时要求重新框选同一区域。

复杂贴图、透明度与穿透管理、长截图、录屏、GIF、图片美化和译文覆盖均移出一期必需范围。上游已有能力可保留或后续开放，但不据此扩大交付标准。

必须实测多屏、负坐标、100/125/150/200% 缩放、混合 DPI 与跨屏选区。DIP、物理像素、裁切与文字框之间的转换以实际图片为准。

### 10.3 调用接口与生命周期

参考项目通过启动 exe、等待退出、读取剪贴板获取图片。旧版区分取消、取色、保存与复制的退出码，Rubick/Tinker 中“非零退出即读图”的简化逻辑不能直接照搬；新版参数和退出协议必须按固定版本重新核对。

截图结果需要绑定会话与实际动作，取消或失败时不得返回旧剪贴板图片。用户或其他程序同期改写剪贴板时，也不能被当作本次截图结果。优先验证可靠的结果通道，必要时增加薄桥接或对选定源码做受控适配。

取字按钮需要复用当前选区图像并调用 OCR 合同。关闭 OCR 时隐藏或禁用按钮并解释原因，不私自拉起另一个识别后端。原生工具现有按钮若不能满足该行为，适配工作属于交付范围，不能以工具自带为由绕过插件启停。

停用或更新时先结束当前会话、处理未保存标注，再停止所属进程和释放资源。强杀进程不等于完成保存协议。配套工具的托盘、快捷键、自动更新和驻留策略要与宿主管理统一，避免出现第二个不可控管理入口。

临时图片与接收插件附件分别确定所有者，接收方持久化完成前不能删除临时资源。原生配置位于独立数据域，更新 npm 包不覆盖用户设置。

### 10.4 独立 OCR 插件：ImageReader

已确定采用 ScreenCapture 配套 ImageReader。用户已确认获得所需授权，按该方案推进，不再将授权核实作为实施门槛；保留原有来源、版本与必要声明。当前评估起点为 1.0.2，实际产物版本与哈希在实施时固定。

已核对的调用链为：ScreenCapture 将当前选区保存为临时 PNG，使用 image-path/del-image 参数启动 ImageReader，自动载入并识别，无需用户重新框选。ImageReader 提供独立结果窗口，左图右文，两侧选区同步，支持 Ctrl+A 全选、Ctrl+C 复制当前选择。

该版本使用 TinyOCR，PP-OCRv6 检测和识别 tiny 模型嵌入 exe。发布物约 25.9 MB，运行不要求用户安装 Python。识别准确率、冷暖耗时、混合 DPI 与部分选字仍需在实际集成路径测试。

原始上游的适配点如下；当前正式集成已经接入宿主结果协议、独立路径与可回收 worker，不能把这些原始行为当作当前仍在使用的执行链。

- ScreenCapture 仅查自身目录或数据目录/plugin 的 ImageReader.exe，需要可配置路径或宿主代理路由，保持两个插件独立版本目录。
- 当前文字输出为系统剪贴板，需增加绑定会话的识别、选择、错误和取消结果通道，供翻译与便签调用。
- ScreenCapture 启动 OCR 后未保留持续管理句柄，需由宿主管理进程与生命周期；OCR 关闭时禁用取字入口，不能打开下载页或擅自启用。
- 当前 OCR 同步在界面线程执行，且每次构建 TinyOCR 实例。实现可响应的任务、取消与退出协作，根据实测决定引擎复用。
- 原生工程使用 Visual Studio C++ 及 Ling、TinyOCR、ONNX Runtime、OpenCV 等依赖，需要清理作者本地绝对路径并建立可重复构建。

模型、进程和结果窗口均归 OCR 插件。关闭结果窗口不等于停用插件；停用、更新应取消任务并释放资源，基础截图仍可用。具体工作与验收见 [实施 TODO](launcher-todo.md) 第 7 节的 P4 任务。

当前宿主通过无窗口 worker 识别，TinyOcr 在请求循环外初始化一次，正常连续任务复用，默认空闲 30 秒协作退出；取消或停用释放 worker，后续请求可重建。结果由独立 React 工作区显示，各任务仍有不同会话和图片资源，当前/上一结果的保留与模型生命周期分开管理。同图新引擎/复用、不同图同 PID/单次初始化、取消和空闲释放证据见[OCR worker 记录](evidence/spark233-ocr-worker.md)；没有把时点内存写成推理峰值或 P95。

### 10.5 翻译与词典插件

采用本地单词词典与长句 AI 双通道，结果标明来源并保留手动切换。默认入口可即时查词，句子提供待执行翻译动作，不能只按字符长度判定。

| 输入                       | 默认处理                     |
| -------------------------- | ---------------------------- |
| 英文单词与词形             | 本地释义、原形、音标、词性   |
| 已收录短语                 | 词典结果                     |
| 句子和段落                 | 提供 AI 翻译动作，执行后请求 |
| 未收录词、术语、人名或缩写 | 提供 AI 解释或翻译入口       |
| 需要上下文的多义词         | 保留词典，允许 AI 上下文解释 |

预装 ECDICT 基础约 76 万词条构建的精简运行数据库与必要词形索引，用户无需 Python，完整版后续可选。核对数据来源和必要声明，以抽样验证词条覆盖，不以例句或音频字段存在就承诺完整内容。多语种词库另定，体积口径见第 6.5 节。

AI 支持服务地址、模型、密钥和目标语言配置，提供原文对照、流式译文、取消、复制和保存便签，保留代码、Markdown、数字和专有名词。

一期使用 OpenAI 兼容 Chat Completions 协议，提供一个当前生效的模型配置，允许自定义地址、模型和密钥。自动识别原文语言，默认非中文译为简体中文、中文译为英文，目标语言可手动修改；密钥未配置时本地词典完整可用。 本地默认方向优先识别假名和韩文，避免含汉字的日语误译英文；纯汉字短语和混合语言有歧义，仍允许手动覆盖，不为判断方向发起网络请求。后台和工作区共用同一纯规则，具体边界见[实施基线](archive/2026-10/spark233-remaining-implementation-2026-10-27.md)。

密钥由宿主管理，页面只读取状态并提交任务。鉴权、限额、超时有明确反馈，不静默切换收费服务。缓存区分文本、语言、模型与影响结果的配置。

截图文字先在本地识别，用户选择文本后送入词典或 AI。网络请求不随每个搜索按键或所有剪贴板变化自动发出。传统翻译 API 聚合与 eSearch 屏幕翻译不作为一期主方案。

## 11. 命令行、MCP 与外部入口

现有命令行、单实例转发和 MCP 继续调用同一业务服务，避免迁移后为启动器、插件界面、CLI 和 MCP 分别维护写入逻辑。

便签命令和 MCP 权限能力在工程拆分中保持可验证，程序入口、环境变量和通信端点采用 spark233 命名空间，不提供旧安装名称兼容。宿主可以预留通用命令路由，但不把便签 MCP 的授权自动扩展为读取剪贴板、截图或其他插件数据。

插件贡献外部可调用能力时，需要稳定命令身份、参数校验、启用状态检查和对应权限。是否向外部 AI 暴露某个插件由显式设置控制。

## 12. 工程组织与实现原则

模块按宿主核心、平台桥接、入口匹配、搜索协调、运行时、SDK、独立 npm 插件和公共 UI 区分。具体目录在代码阶段按依赖图确定，不先做无目标全仓搬迁。

业务插件独立构建版本化，页面与业务不静态绑定宿主。预装包升级使用相同 npm 版本管理，ScreenCapture 原生文件也位于可替换插件产物中。

自研 Web 界面使用 React + shadcn/ui。SDK、模式与能力合同是边界，不强迫第三方插件共享 React 实例，也不重写 ScreenCapture 的原生界面。平台资源在构建时准备，客户端不执行安装脚本或运行时编译。

测试隔离配置、数据、索引、插件和原生程序配置目录，不读写真实便签或历史。保留仓库已有未提交修改。

| OCR               | 中英文、图文映射、取消、后端资源和模型释放                           |
| 翻译              | 词形与短语、AI 主动执行、流式取消、错误和缓存隔离                    |
| 发布包            | 离线首装、基础词库、npm 平台资源、ASAR、模型服务、体积与完整进程树   |

第三方已有能力仍需通过本项目实际调用路径验收。MVP 以少量代表场景验证截图、输入、焦点、多格式和多屏，不为每种格式、平台组合或同构分支新建一组测试；原有便签胶囊未完成人工验收项继续保留。

新增自动化用例默认不做。只有现有检查无法证明、且涉及数据丢失或恢复、权限与信任隔离、关键生命周期或并发不变量、已出现真实回归时，才补最小必要用例。能加强已有用例时直接复用，一个风险在合适的最低层证明一次；不为接线、常量、文案、组件样板、第三方输出或覆盖率数字加测试，不引入只为测试存在的新框架和复杂脚手架。

保留已有有效测试，不以 MVP 为由删除失败断言或跳过真实故障。技术栈升级、模块边界变更及阶段收口运行一次相关回归，日常小改动只运行受影响检查；没有新变化或未解决问题时不反复执行整套测试或全场景矩阵。数据隔离、保存恢复、权限拒绝和关键链路能实际运行仍是交付条件。

每阶段只选择能证明新增能力的少量代表场景，复用已有样本、脚本和证据。一个 TODO 不对应一个新用例、脚本或独立报告；正式集成只补宿主接入新增的行为，已经证明的底层能力不重复测试。尚未实现的界面、焦点交互和性能随对应功能验收；没有现成设备的 DPI 或环境组合记录为未验证，不为凑齐矩阵搭建额外测试设施。已知失败需要处理或明确记录，未验证项不能写成支持结论。

### 13.2 性能测量

固定机器和少量代表数据，随功能落地记录冷启动、常驻呼出、命令匹配、本地查词、模式查询、索引更新、原生截图就绪、OCR 冷暖识别、AI 首段与包下载切换中相关的指标。MVP 先记录少量重复测量的原始耗时、样本数量与范围，只有样本足够时才报告分位数；不把单次小样本结果当成稳定性能保证。记录影响结果的文件量、正文量、图片、模型和屏幕 DPI。

按完整进程树测量宿主、便签、索引、剪贴板、ScreenCapture、OCR 及插件停用后的 CPU、内存、磁盘、残留窗口进程。不能仅凭原生小文件或组件宣传判断更快。

P0 建立现有应用基线，P1 后的原生前置验证固定机器、少量代表数据和 OCR 样例，为当前可调用的搜索、截图和 OCR 形成初始性能、质量与资源预算。启动器呼出及正式插件进程树随 P3–P6 实现补齐，P7 按相同口径收口。MVP 使用可重复的实际测量，不先建设性能测试平台或大规模样例库；各能力实现时明确通过条件，不到发布前才定义，也不在实测前承诺延迟、内存或准确率数字。

### 14.2 一期必需交付链路

1. 快捷键截图 → 框选与标注 → 复制或保存；取消不改写原剪贴板。
2. 当前截图选区点击取字 → 本地识别 → 全部或部分复制，无需重新框选。
3. 识别文本 → 词典或 AI 翻译 → 复制或保存便签。
4. 输入英文单词 → 即时本地释义；输入句子 → 执行 AI 翻译动作。
5. 输入文件搜索关键词 → 进入模式 → Pulse 文件名或 Instant 正文结果 → 筛选、打开或定位。
6. 复制文本、图片、文件 → 历史记录 → 进入剪贴板搜索 → 回贴原应用。
7. npm 查询新版本 → 校验下载 → 单独更新截图插件，便签和剪贴板保持可用。
8. 停用 OCR → 任务和资源释放，基础截图与标注仍可用。
9. 停用某个搜索插件 → 对应模式和结果撤下，其他命令和来源继续工作。
10. 历史收藏、置顶、标签备注与编辑恢复 → 搜索或批量合并 → 快捷回贴；图库、表情符号和便捷小窗使用同一数据源。
11. 普通历史超出用户设置范围 → 进入待清理 → 调整范围恢复显示，或确认清理并回收无引用资源。
12. 全新 spark233 安装 → 首次引导和默认插件 → 离线截图、OCR、查词 → 后续启动恢复便签并驻留托盘。

独立启停和更新为一期架构条件。阶段内临时适配有移除点，不永久保留并行业务状态或第二套写入逻辑。

## 15. 当前范围外事项与后续决策

一期不建设 Cloudflare 服务、自定义网页上传发布后台或自建 registry。完整插件市场、账户、云同步、uTools API 兼容、PDF/Office 正文解析、向量搜索暂不纳入。
