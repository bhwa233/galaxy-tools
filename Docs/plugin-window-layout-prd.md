# 插件独立窗口布局统一 PRD

日期：2026-10-30

版本：v0.3

状态：已授权并完成文件搜索、词典与翻译、剪贴板历史、OCR 的布局修改；截图历史待评审，快捷剪贴板保持现状。尚未打包发布。

## 1. 目标与背景

以「便签管理」窗口为视觉参考，统一插件独立窗口的标题栏外观和窗口控制体验。各插件仍保留适合自身业务的布局，以及用户已经熟悉的功能入口位置。

当前不同窗口的顶部承担了不同职责：便签管理有独立标题栏；文件搜索把搜索框放在顶部；OCR 顶部是文字操作；截图历史顶部是数量和清理操作。统一设计需要逐个确定，不能将这些功能机械地集中到右侧，也不能默认全部下移到第二行。

评审后的预期结果：用户可以辨认窗口属于同一个应用，同时能在原有区域找到常用功能。

## 2. 已确认原则与决策边界

### 2.1 已确认原则

1. 顶部栏的视觉参考是便签管理。
2. 非必要不集中功能到右侧，保持原有插件功能入口位置。
3. 逐个插件确认布局，不以一套强制布局替代所有现有界面。
4. 用户已明确授权上述四类窗口的界面实现；截图历史待确认，快捷剪贴板本轮不修改。

### 2.2 本文中的建议尚未确认

以下内容仍待评审；各插件已确认结论见第 5 节和第 8 节：

- 截图历史采用独立标题行，还是标题与管理工具合并单行。

特别说明：不要求每个窗口补齐「设置」「关于」「快捷入口」三个按钮。便签现有入口继续保留；其他插件已有的入口按自身布局保留，不因统一外观而新增相同入口。

本轮不调整启动器、插件市场、插件配置页面、截图选区、贴图、便签胶囊及其他特殊悬浮形态。第三方插件自行绘制的窗口也不直接套用；如后续要求覆盖，需另行确认宿主可控制的范围。

本轮不增加业务能力，不修改查词、翻译、搜索、记录、清理或跨插件发送流程。

## 4. 共用视觉与交互建议

### 4.1 外观

| 项目           | 建议要求                                         |
| -------------- | ------------------------------------------------ |
| 常规标题栏高度 | 48px，与便签管理一致                             |
| 背景与边界     | 跟随当前主题，底部一条细分隔线；不增加独立大色块 |
| 标题           | 左侧显示当前窗口名称，使用便签管理同级字体与字重 |
| 图标按钮       | 与便签管理使用相同的尺寸、间距和悬停反馈         |
| 窗口控制       | Windows 最右侧固定为最小化、最大化/还原、关闭    |
| 功能与控制分隔 | 同行存在业务功能时，在窗口控制前保留分隔线       |
| 关闭反馈       | 沿用便签管理的危险色悬停反馈                     |
| 关于与更新     | 保留便签现有行为，不自动复制到其他插件           |

48px 是常规标题行的建议高度，不限制下方业务工具栏的高度。若现有文字按钮无法容纳，应在该插件方案中单独处理，不通过压小字体统一塞入。

### 4.2 功能位置保留的含义

- 现有左侧搜索入口仍在左侧，现有左侧导航仍在左侧。
- 现有右侧历史、刷新、设置等入口仍留在右侧，不因统一而移动到其他页面或菜单。
- 保留功能分组和顺序，允许为窗口控制增加间距及分隔线。
- 确需新增标题行、移动整个工具栏时，必须在对应插件中明确列出并评审。
- 布局统一不改变按钮的作用、可用条件和状态提示。

### 4.3 窗口交互

- 标题栏空白区域支持拖动，双击可拖动空白区域执行最大化/还原。
- 搜索框、按钮和其他可交互元素正常响应点击、输入、选择，不触发拖动或双击最大化。
- 最大化后按钮显示还原状态；还原后恢复原有窗口尺寸与位置行为。
- 点击关闭沿用当前窗口自己的关闭流程；有取消任务、保存确认等步骤时，必须完整保留。
- 最小化和最大化不重置输入、结果、选中项、滚动位置或正在执行的业务任务。
- macOS 保留平台原生窗口控制位置，避免与标题和功能入口重叠；本轮视觉评审优先以 Windows 为准。

### 4.4 窄窗口

窗口控制始终可见，不被标题或业务功能挤出。标题可以省略显示；已有搜索框可以在合理范围内收缩，但不能小到无法正常输入。

当同行布局已经无法使用时，优先明确该插件的最小窗口宽度；如需业务工具栏换行，应保持按钮分组及顺序，并在对应插件中确认。未经确认不把常用入口隐藏进「更多」菜单。

## 5. 逐插件方案

### 5.1 便签管理：保留基准

**当前布局**：左侧「便签管理」，右侧依次为快速记事、配置、关于/更新，分隔线后为窗口控制。下方左侧为便签列表，右侧为编辑区及编辑工具栏。

**建议**：保留当前布局，作为其他窗口的视觉基准。编辑工具、便签搜索、新建入口及状态栏不调整。不要因其他窗口适配反过来改变便签的功能分组。

**N1 本轮处理**：便签管理保持原样，仅作为参考基准。

### 5.2 文件搜索：两种布局供选择

**当前布局**：顶部左侧为搜索框、文件名/内容切换，右侧为加载状态、配置、关闭。主体在文件名模式下为左侧分类和右侧结果列表；内容模式沿用现有结果布局。

| 方案                      | 标题区域                                                   | 搜索与配置区域                                         | 取舍                                                     |
| ------------------------- | ---------------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| A：保留单行，优先减少移动 | 顶部仍以搜索框开头，不额外插入占位标题；最右侧补齐窗口控制 | 搜索框、模式切换、加载状态、配置保持当前顺序与左右关系 | 改动小、节省垂直空间；需保证足够拖动空白，窄窗口压力较大 |
| B：独立标题行             | 新增「文件搜索」标题行，右侧仅放窗口控制                   | 原有搜索、模式切换、加载状态、配置整体保留在下一行     | 标题结构最接近便签；增加一行高度，搜索区域整体下移       |

**用户已确认 S1：选择 B，独立标题行。** 顶部左侧为「文件搜索」，右侧为窗口控制；原搜索框、模式切换、加载状态和配置保留在下方同一工具栏，维持原有顺序与左右关系。A 仅作为评审备选记录。

**保留行为**：启动器带入关键词后自动搜索；文件名/内容模式切换、左侧分类、结果排序和现有结果操作不改变。

**S2 状态**：针对 A 的窄窗口问题不再适用；B 仍需保证搜索工具栏在最小允许宽度下可正常使用。

### 5.3 词典与翻译：保留左侧导航和历史入口

**当前布局**：顶部左侧为「词典与翻译」，右侧在 AI 翻译视图显示翻译历史入口，随后为关闭。左侧导航为本地词典、AI 翻译、搜索历史。词典查询和翻译操作位于各自内容区。

**建议布局**：

- 顶部沿用当前结构，调整为与便签一致的标题栏外观。
- 翻译历史入口保留在右侧，随后增加分隔线及窗口控制。
- 左侧三个导航项的位置和顺序保持不变。
- 查词输入、候选词和释义保留在词典内容区；翻译操作仍留在翻译内容区。
- 本地词典的搜索历史与 AI 翻译历史继续保持各自现有入口，不合并。

**保留行为**：带词打开并自动查词、自动显示首个匹配词释义、候选切换、历史回查，以及切换导航时的现有任务和内容保留行为。

**用户已确认 T1**：按上述推荐布局处理，保留「词典与翻译」标题、右侧翻译历史入口和左侧导航。

### 5.4 剪贴板历史：现有顶部功能继续同行

**当前布局**：顶部左侧为「剪贴板历史」，右侧为快捷剪贴板、暂停/恢复记录、配置和关闭。下方为搜索与类型筛选，再下方为列表和详情。

**建议布局**：

- 保留当前顶部左右分组和功能顺序，统一标题栏外观。
- 配置之后增加分隔线和完整窗口控制，不增加关于入口。
- 搜索、类型筛选、收藏筛选、列表及详情均保留现有位置。
- 暂停/恢复记录继续显示文字和状态，避免为塞入标题栏改成含义不明的图标。

**空间约束**：此窗口顶部文字按钮较多。优先通过合理最小宽度保证同行可用；如果需要将操作组移到下方，需作为另一个方案单独确认，不默认执行。

**用户已确认 C1**：按上述推荐布局处理，保留顶部功能同行及原有顺序，增加窗口控制；窄窗口遵循本节空间约束。

### 5.5 截图历史：新增标题行，保留管理工具分组

**当前布局**：顶部左侧显示截图数量，右侧为刷新、清空和关闭，下方为截图卡片。当前缺少独立的文字标题行。

**建议布局**：

- 新增 48px 标题行：左侧「截图历史」，右侧为窗口控制。
- 原数量与管理工具组整体保留在标题行下方：数量靠左，刷新、清空靠右，保持原有顺序。
- 移除原工具组中的窗口关闭按钮，避免出现两个窗口关闭入口。
- 卡片、卡片操作、加载反馈、错误与重试区域保持现有逻辑。

**影响**：管理工具整体下移一行，可视卡片区域减少对应高度。此处新增标题行属于明确的布局变更，需要单独确认。

**备选**：若优先保持原有垂直位置，可采用单行「截图历史 + 数量」，右侧为刷新、清空、分隔线及窗口控制；需评估窄窗口是否拥挤。

**待确认 H1**：选择新增标题行，还是标题与管理工具合并单行？

### 5.6 OCR 取字结果：标题与文字操作分开

**当前布局**：顶部左侧依次为全部文字、复制所选文字、查词、AI 翻译、保存便签，右侧为关闭。下方为原图选区与可编辑识别结果，没有独立标题行。

**建议布局**：

- 新增 48px 标题行：左侧「取字结果」，右侧为窗口控制。
- 现有文字操作组保留在内容区顶部靠左，顺序不变；保留现有换行能力。
- 移除原操作组的窗口关闭按钮。
- 原图与文字区域继续沿用当前响应式布局，不新增侧栏或步骤。
- 查词、翻译、保存便签的可用条件、禁用提示及发送内容保持当前行为。

**影响**：操作组整体下移一行；新增标题栏应固定在顶部，内容滚动不带走窗口控制。

**用户已确认 O1**：新增独立标题行，现有文字操作组保留在其下方靠左，顺序不变。

### 5.7 快捷剪贴板：作为紧凑形态单独确定

**当前布局**：顶部左侧为「快捷剪贴板」，右侧为暂停/恢复记录、配置和关闭；下方为搜索、筛选和单列内容。其操作密度和窗口尺寸与剪贴板历史不同。

**用户已确认 Q1：快捷剪贴板先不变。** 本轮保持当前布局、标题栏高度、功能入口和窗口控制，不套用本次常规窗口的视觉调整。

后续若要统一此紧凑形态，再单独提出方案评审。

## 6. 状态、异常与数据保护

1. 加载状态仍出现在该插件当前的状态区域，不能占据关闭按钮或覆盖工具入口。
2. 空结果、服务未就绪、查询失败、权限不足等继续在内容区提供反馈，不只在标题栏显示一个图标。
3. 窗口大小变化不能清空搜索词、查词结果、OCR 编辑文字或便签内容。
4. 最小化不等于关闭，不停止记录，也不自行取消正在进行的搜索或翻译。
5. 关闭继续调用每个窗口现有流程。便签保存失败或确认超时，不能因此自动终止仍在运行的业务进程。
6. 插件停用、能力不可用时，保留原有禁用和提示规则，不因按钮换位改变权限边界。
