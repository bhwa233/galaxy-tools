## 1. 窗口呈现与职责

| 窗口               | Windows 任务栏                                       | 失焦处理                                          |
| ------------------ | ---------------------------------------------------- | ------------------------------------------------- |
| 启动器搜索面板     | 不显示独立任务栏按钮，通过已有快捷键、托盘等入口呼出 | 用户转向窗口外部时隐藏，内部临时交互按第 2 节处理 |
| 独立设置窗口       | 正常显示任务栏按钮                                   | 保持普通窗口行为，不随启动器一起隐藏              |
| 便签及其他插件窗口 | 沿用各自既有规则                                     | 不因本方案统一改成启动器行为                      |

实现应按启动器搜索面板的明确身份应用规则，不能仅按共用的 `view: launcher` 批量设置。独立设置页复用宿主角色，不代表它也应跳过任务栏或失焦隐藏。本次确认的是任务栏按钮，不额外约定 Alt+Tab 或任务视图中的呈现。

## 2. 点击外部隐藏

- 启动器显示时，点击窗口外的桌面空白、任务栏或其他应用，隐藏启动器；本方案中的“空白位置”指窗口外部。
- 点击启动器内部空白不隐藏。搜索、滚动、应用选择、结果操作均保留正常交互。
- 不新增覆盖桌面的透明遮罩，也不吞掉外部点击；该次点击仍作用于原位置。优先复用宿主窗口焦点事件及现有焦点守卫，避免新增全局鼠标监听。
- 内部菜单、中文输入法候选及由当前操作打开的原生文件/目录选择器不能被误判为外部切换。临时保护与实际操作生命周期绑定，结束或失败后释放，不能永久阻止隐藏。
- 打开独立设置成功后隐藏启动器，设置窗口继续显示；打开失败则保留启动器并显示错误，不让用户失去错误反馈。
- 隐藏只收起面板，不退出应用，不直接取消业务保存或关闭插件工作区。查询会话仍按既有规则失效，迟到结果不得重新弹出窗口；业务任务的取消、排空与关闭继续遵循原有合同。
- 系统失焦事件能否覆盖桌面空白点击，以及真实 IME、选择器焦点边界，需要 Windows 人工确认。不能用浏览器失焦模拟替代这些结论；若发现系统例外，先记录再讨论最小补充方案。

## 3. 同时显示的两个结果区域

```text
┌──────────────────────────────────────┐
│ 搜索框                          设置 │
├──────────────────────────────────────┤
│ 应用图标  应用图标  应用图标       → │
├──────────────────────────────────────┤
│ 信息标题                             │
│ 摘要、路径或结果说明                 │
│──────────────────────────────────────│
│ 文件、词典或其他信息结果             │
└──────────────────────────────────────┘
```

| 区域             | 展示内容                                                  | 展示与操作                                               |
| ---------------- | --------------------------------------------------------- | -------------------------------------------------------- |
| 顶部搜索框       | 当前关键词，右侧保留设置入口                              | 呼出后自动聚焦，保留正常文本编辑与输入法行为             |
| 横向应用与插件区 | 匹配应用、插件功能/模式入口的图标、名称和必要的可用性状态 | 单行排列，超出时横向滚动；点击或键盘确认后执行或进入模式 |
| 纵向信息区       | 当前查询范围内的文件、目录、词典/翻译等信息结果及说明     | 纵向列表，长内容在区域内滚动，支持既有结果动作           |

- 两区共用一个搜索词，同时呈现，各自允许异步更新；快结果不等待慢来源。某一区域没有结果时收起该区域及空标题，仍在查询的区域显示加载状态。
- 所有适用来源结束后，两区均无结果才显示统一空结果提示。失败来源显示对应错误和重试，不伪装成无结果，也不阻断另一地区域的有效结果。
- 应用与信息按既有宿主可信结果类型及目标身份分类，不从展示标题、图标或 renderer 自带路径猜测类型；同一应用不因布局拆分重复进入两区。
- 保留既有固定、隐藏、排序、别名、插件可用性及结果执行校验。分批更新尽量保持当前选中项，不因迟到结果改变用户即将执行的目标。
- “同时显示”是布局规则，不等于默认开启所有正文来源。文件、便签和剪贴板仍按既有模式/来源合同查询；AI 请求仍只由用户明确执行触发。
- 进入专门模式后，两区只展示该模式实际返回的内容，不额外混入与该模式无关的全局应用结果。无应用结果时应用区自然收起。
- 精确窗口尺寸、应用卡片宽度及首屏数量留待视觉细化，按可用工作区适配，不在本次讨论中凭空固定。

## 4. 键盘与搜索范围

用户随后明确不需要“关键词＋Tab 进入模式”。目标方案移除该快捷操作，Tab 只负责正常焦点导航，不再识别输入中的关键词并切换模式。当前源码仍有旧分支，待用户明确要求开始写代码后再移除；旧模式快捷键通过记录属于历史输入，不作为目标行为保留。

模式仍表示查询范围，与横向/纵向布局无关。需要限定范围时，通过点击或键盘选择“搜索文件”“搜索便签”等已有入口进入；进入后明确显示当前范围，并提供返回全部入口的操作。移除的是额外的 Tab 触发方式，不删除已有搜索能力。

双区域键盘规则：

- 输入框内左右键继续移动光标，不能无条件被应用区截获；中文输入法组合期间不执行模式切换或结果动作。
- 输入框中的 Tab 按可访问焦点顺序进入结果/控件，无论输入是否恰好匹配关键词，都不切换模式。Shift+Tab 保留反向焦点导航。
- 焦点进入横向应用区后，左右键选择应用；进入纵向信息区后，上下键选择信息结果。Tab/Shift+Tab 在可操作区域和控件之间移动，不建立困住焦点的循环。
- Enter 执行当前有焦点的操作或选中结果；只触发一次。异步结果更新不应偷取焦点或跳到另一地区域。
- Esc 沿用分层返回：先关闭局部菜单/弹层，再退出当前模式，普通入口中再按 Esc 隐藏启动器。模式输入为空时的退格返回沿用现有能力，不把所有 Esc 一律改为隐藏。
- 进入模式后显示明确模式标识、输入提示和返回入口。显示布局不切换成另一个独立窗口；返回后旧模式查询和迟到结果不能重新填回。

## 5. 后续实施与验证计划

仅在用户明确要求写代码后执行，顺序仍为单线程集中修改、最后统一验证：

1. 区分启动器、设置和插件窗口身份，接通仅启动器跳过任务栏及焦点隐藏规则，复用已有调用方、会话与焦点守卫。

3. 移除关键词＋Tab 进入模式的分支，统一键盘选择与焦点导航；保留点击/回车进入搜索范围，与设置窗口及管理入口整合一并收口。
