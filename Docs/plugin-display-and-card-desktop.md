# 启动器、插件窗口与卡片桌面方案

日期：2026-11-10。宿主弹层方案补充确认：2026-11-12。

状态：已与用户确认，正在分支 `codex/plugin-window-framework` 实施。本文是目标行为，实施与验收范围见[进度记录](plugin-window-framework-progress.md)，未验收部分不表示已经交付。

本方案先确定启动器作为插件宿主的整体框架，再定义插件窗口在普通桌面和卡片桌面中的展示。涉及命令入口、窗口声明、显示环境、标题栏、添加、关闭、多屏布局和恢复的交互，以本文为准；[原状态栏方案](plugin-window-status-bar.md)与[桌面窗口层设计](desktop-widget-layer.md)中不冲突的技术边界和历史验证记录继续作为参考。实施入口见 [TODO](launcher-todo.md)。

SDK、实例／展示存储、窗口协调、承载接入、迁移和代码文件改动见[技术方案](plugin-window-framework-tech-design.md)。

## 1. 整体框架与职责

### 1.1 宿主、启动器与卡片桌面

整体关系为：**宿主管理插件，插件声明命令和窗口，窗口在普通桌面或卡片桌面展示。**

| 部分               | 职责                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| 插件               | 提供业务功能、共享数据、后台任务，声明公开命令和支持的窗口；允许没有窗口，不强制提供主窗口     |
| 启动器             | 搜索应用、插件和公开命令，提供快捷操作、搜索结果、简短预览；持续编辑和完整业务操作进入插件窗口 |
| 插件窗口           | 插件公开的一种具体界面，声明名称、尺寸、标题栏和复用等能力，可有多个窗口类型                   |
| 普通桌面           | 展示插件独立窗口，包括管理界面、单条便签、网速悬浮窗                                           |
| 卡片桌面           | Spark 的独立整屏工作窗口，集中展示和操作用户添加的插件业务窗口，管理面板排列和显示             |
| 宿主设置与窗口管理 | 管理插件安装、启停、权限和快捷键，统一处理窗口展示、操作、生命周期与恢复                       |

启动器与卡片桌面读取同一份插件信息，但生成不同入口：**启动器读取公开命令，卡片桌面读取插件明确声明可添加的业务窗口。** 窗口声明不自动成为启动器搜索项；插件需要通过公开命令提供对应的打开入口。

快捷操作只放在启动器。卡片桌面不提供命令快捷按钮、动作磁贴或单独的快捷操作区域；面板内正常的业务操作继续保留。

### 1.2 插件声明可用窗口

插件可以不声明窗口，也可以声明一个或多个窗口类型。单条便签和网速悬浮窗都是插件额外提供的独立窗口，不是宿主另外定义的一套卡片类别。

| 插件             | 窗口类型示例         | 关联公开命令示例         |
| ---------------- | -------------------- | ------------------------ |
| 便签             | 便签管理、单条便签   | 打开便签管理、新建便签   |
| 流量监控         | 流量详情、网速悬浮窗 | 打开流量监控、显示网速   |
| 翻译             | 词典翻译窗口         | 打开词典翻译             |
| 纯动作或后台插件 | 可以没有窗口         | 执行转换、暂停采集等动作 |

每个窗口分别声明以下产品能力，具体字段在实施时设计，本文不生成 SDK 配置或代码：

- 稳定的窗口标识、名称、图标和界面入口。
- 是否允许添加到卡片桌面。只有明确允许的业务窗口进入添加列表。
- 默认尺寸、最小尺寸，以及是否允许缩放、最小化、最大化等窗口能力。
- 是否显示宿主标题栏，默认显示，可由插件开发时声明隐藏，用户不能覆盖。
- 实例复用方式：单实例、按文档或内容标识复用、允许创建多个。
- 窗口用途：可持续使用的业务窗口，或设置、确认、文件选择等临时交互；原生文件对话框等也需按临时交互处理，不要求都成为可公开添加的窗口定义。
- 从不同入口创建或打开时所需的业务参数与处理方式，例如新建便签或打开某个便签 ID 对应的内容。
- 恢复已有窗口所需的内容标识、参数与启动恢复策略。创建新内容和恢复已有内容是不同操作，不能共用一个无条件新建的入口。

完整界面和精简外观仅是插件窗口的不同设计，不形成两套面向用户的分类或两套添加协议。底层承载可以不同，现有声明式 HUD、宿主可信窗口、隔离 Web 窗口和 uTools 窗口按能力接入统一窗口管理。

### 1.3 两种显示环境

| 环境     | 行为                                                                                   | 内容示例                                 |
| -------- | -------------------------------------------------------------------------------------- | ---------------------------------------- |
| 普通桌面 | 作为独立窗口显示，默认使用正常窗口层级，可单独置顶；最小化、最大化和缩放按窗口声明提供 | 便签管理、流量详情、网速悬浮窗、单条便签 |
| 卡片桌面 | 类似手机负一屏的独立整屏界面，集中排列插件声明可添加的业务窗口                         | 同一批窗口类型在卡片桌面内混排           |

显示环境决定窗口出现在哪里，窗口声明决定它有哪些能力。卡片桌面中的“面板”是业务窗口在该环境中的展示称呼，不是另一种插件业务类型。

网速悬浮窗、便签卡片属于普通桌面上的精简窗口形态，不再额外引入“固定在普通桌面”状态或「固定到桌面」操作。置顶是普通桌面独立窗口的附加属性，按当前这处展示保存；卡片桌面及其中的面板没有置顶、最小化和最大化。

## 2. 窗口类型、实例与展示关系

- **插件运行与业务数据**：由插件管理。多个窗口共享业务数据，添加窗口不应重复启动剪贴板监听、流量采集等同一后台能力。
- **窗口类型**：插件声明的窗口定义，例如便签管理、单条便签、流量详情、网速悬浮窗。窗口类型和某篇便签对应的实际窗口不是同一层概念。
- **窗口实例**：实际打开的具体界面，可能绑定便签 ID 等内容标识；复用或新建由窗口声明和当前操作决定。
- **展示关系**：一个窗口在某个环境中的展示记录，保存该处的位置、尺寸、层级和显示状态。

多个可独立交互的窗口分别保留搜索词、滚动位置、选中项等操作状态，业务数据保持共享。允许同一插件在不同环境展示，也允许重复添加；不设置“每个插件只能有一个面板”的产品规则。单实例或按内容复用的窗口采用第 8 节的规则。

各展示关系的属性独立：调整普通桌面上的尺寸或置顶状态，不改变卡片桌面里的布局。卡片桌面跨屏共用布局，见第 7 节。

## 3. 入口、打开与添加

### 3.1 添加列表来自窗口声明

卡片桌面维护自己的内容清单。普通桌面打开窗口不会自动加入卡片桌面。

顶部「＋」按“插件 → 可添加窗口”组织，并支持搜索。例如流量监控下列出流量详情、网速悬浮窗，便签下列出便签管理、单条便签。不再按完整窗口／精简卡片划分目录，也不把公开命令、设置弹窗或确认框混入窗口添加列表。

窗口名可附用途说明。列表及分组从插件声明生成，宿主不按便签、流量等具体业务硬编码可添加项。

### 3.2 打开、添加与业务参数

| 入口或操作                                   | 结果                                                                                                                       |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 启动器执行公开命令                           | 执行动作或打开命令指定的窗口；打开窗口默认进入普通桌面，卡片桌面若展开则先收起并聚焦目标。无窗口动作不要求收起卡片桌面     |
| 普通「打开」                                 | 先复用目标环境中符合窗口类型及内容标识的实例；允许多实例但目标环境没有匹配窗口时新建，单实例或按内容复用的窗口再跨环境查找 |
| 卡片桌面「＋」选择支持多个实例的窗口         | 新增窗口和面板，原面板保留，卡片桌面保持打开                                                                               |
| 卡片桌面「＋」选择单实例窗口                 | 复用并接入原窗口，不强制创建第二个实例                                                                                     |
| 卡片桌面「＋ → 便签 → 单条便签」             | 新建一篇便签，直接在卡片桌面编辑；不弹出已有便签选择器                                                                     |
| 便签管理中选择已有便签，再「添加到卡片桌面」 | 将指定便签加入卡片桌面，不新建便签正文                                                                                     |
| 卡片桌面「＋ → 流量监控 → 网速悬浮窗」       | 直接添加对应网速窗口                                                                                                       |
| 窗口的「添加到卡片桌面」                     | 对声明允许添加的业务窗口建立展示记录；保留原环境关系，单实例按接入与归还规则处理                                           |
| 卡片桌面面板的「独立窗口打开」               | 收起卡片桌面，在普通桌面显示并聚焦目标；保留卡片桌面的添加记录及布局                                                       |

窗口负责显示什么、入口负责新建还是打开已有内容，由插件定义。宿主接收窗口标识和插件传入的业务参数，不内置便签选择器或其他插件的内容选择逻辑。便签的新增与已有内容使用上述两个明确入口。

### 3.3 创建与恢复分开

- 首次通过「＋」新增时执行窗口对应的创建操作；涉及新建业务内容时，由插件返回已创建内容的稳定标识，并与窗口及展示记录关联保存。
- 例如新建便签成功后，保存该篇便签 ID。再次展开卡片桌面、应用重启或故障重试时，按该 ID 打开已有便签，不再次执行新建便签。
- 便签管理、流量详情等不需要新建业务内容的窗口，按窗口标识和已保存的恢复参数打开，不因恢复新增业务数据。
- 恢复失败不能通过重新创建业务内容掩盖错误；按第 9 节显示对应状态。内容已明确删除时清理展示记录。

### 3.4 插件内部打开按目标窗口能力跟随环境

以下跟随规则以目标业务窗口明确声明支持卡片桌面为前提。支持条件对「＋」、插件内部打开、已有内容添加及历史恢复都生效，不能因为调用来自卡片桌面就绕过声明。

- 在普通桌面的网速窗口打开流量详情，详情作为普通桌面独立窗口显示。
- 在卡片桌面的网速窗口打开声明支持的流量详情，详情在卡片桌面内打开。
- 在卡片桌面的便签管理中编辑便签，声明支持的编辑器留在卡片桌面；同一便签已有编辑器时复用。
- 普通「打开」仍优先定位已有实例，「＋」按窗口能力新增。
- 卡片桌面内打开的业务窗口形成展示记录，保留到下一次呼出，直到用户关闭；不额外区分临时业务面板和永久业务面板。
- 用户明确选择「独立窗口打开」时才转到普通桌面；启动器来源遵循第 3.2 节的普通桌面默认规则。
- 设置、确认、文件选择等临时交互依附当前界面，关闭后不进入卡片桌面的长期清单。

未声明支持的业务窗口不进入卡片桌面，也不生成长期面板记录；可继续通过原有普通桌面入口使用，不把它强行嵌入。设置、确认、文件选择等临时交互按其用途依附当前界面，不等同于可添加的业务窗口。菜单不提供「固定到桌面」。

不增加面板别名或自定义命名功能，继续使用插件窗口名称、便签标题等现有名称。空卡片桌面不提供引导或推荐面板，不自动添加内容，保留顶部「＋」入口。

## 4. 标题栏声明、操作与关闭语义

### 4.1 插件按窗口声明是否显示标题栏

- 默认显示完整的宿主标题栏，未声明的窗口采用此默认值。
- 插件开发时在各窗口声明中确定是否显示宿主标题栏，不按整个插件统一关闭。同一插件的详情窗口与悬浮窗可以采用不同声明。
- 用户不能覆盖该声明，不提供“显示／隐藏标题栏”的用户设置或菜单项。
- 声明在普通桌面和卡片桌面都生效；显示标题栏时，其中的按钮由当前环境和窗口声明共同决定。
- 隐藏的是宿主标题栏，不是插件自己的业务工具栏。插件可以自行设计内容和业务控件，不再额外叠加一条宿主标题栏。

| 窗口类型     | 标题栏声明 | 内容处理                                                 |
| ------------ | ---------- | -------------------------------------------------------- |
| 流量详情窗口 | 显示       | 使用完整宿主标题栏                                       |
| 网速悬浮窗   | 隐藏       | 保留紧凑网速数据区域，不强制添加常驻或悬停标题栏         |
| 便签管理窗口 | 显示       | 使用完整宿主标题栏，保留管理功能                         |
| 单条便签     | 隐藏       | 沿用便签自己的标题输入、MD／文本、提醒、折叠等业务工具栏 |

这是待实施的产品配置规则，不表示当前 SDK 已支持对应声明。具体字段、旧声明兼容和校验方式在实施时统一设计。

### 4.2 根据环境提供操作

所有窗口采用一致的操作含义，保留各自必要的业务操作。标题栏可见时按下表呈现；标题栏隐藏时，由插件自行安排按钮及菜单，通过宿主 API 调用对应窗口操作或展示宿主窗口菜单。

| 显示环境 | 宿主允许的窗口操作                                                                               |
| -------- | ------------------------------------------------------------------------------------------------ |
| 普通桌面 | 置顶、更多、关闭；最小化、最大化／还原、缩放按该窗口的声明提供，不按完整／精简分类硬编码         |
| 卡片桌面 | 更多、关闭，缩放按窗口声明提供；环境统一禁止置顶、最小化和最大化，即使窗口在普通桌面支持这些操作 |

标题栏显隐与可操作能力分别声明：隐藏标题栏不等于插件失去全部窗口操作，显示标题栏也不强制小窗口具备最大化。便签折叠等属于窗口业务操作，继续由插件提供。

插件自行控制业务菜单及其触发方式，宿主不强制替换内容区或拖动区的右键菜单。宿主提供窗口操作 API 和窗口菜单 API，允许插件在自己的按钮、菜单或右键交互中接入。调用作用于对应窗口，实际效果遵循当前环境和窗口能力，不能因自绘控件或隐藏标题栏而绕过约束。卡片桌面的面板列表继续提供定位、关闭等宿主管理入口，不依赖插件自绘关闭按钮。

显示标题栏时保留可拖动区域；隐藏时由窗口明确划分拖动区与交互区。便签输入框、按钮不参与拖动；网速数据区域可拖动，拖动结束不触发打开详情。缩放按窗口声明提供，尊重最小可用尺寸。便签现有折叠、贴边和展开能力继续保留。

卡片桌面中的面板可以重叠，点击面板使其位于其他面板前方，不设置持续置顶分组。双击标题栏不最大化，其他窗口操作入口也不能绕过该环境规则。

所有关闭按钮统一使用「关闭」文案，不使用「移出桌面」「移出卡片桌面」作为按钮名称。

### 4.3 关闭当前展示与收起整体界面

| 关闭对象       | 结果                                                               |
| -------------- | ------------------------------------------------------------------ |
| 某个窗口或面板 | 关闭当前这一处展示，取消该处展示记录；保留业务数据和其他位置的展示 |
| 整个卡片桌面   | 仅收起界面，保留全部面板、布局和操作状态；下次唤起恢复             |
| 停止插件       | 通过单独的停止操作执行，不与关闭混用                               |

关闭展示不能丢弃未保存内容；需要保存时沿用保存流程。保存失败或确认超时，不得自动结束运行中的业务进程。

关闭当前展示不等于销毁一个仍被其他展示关系使用的单实例窗口。单实例窗口被卡片桌面借用时关闭该面板，只取消卡片桌面的记录；仍需在普通桌面显示的窗口恢复原展示。只属于卡片桌面的窗口关闭后不自动转成普通桌面窗口。具体接入、归还和收起规则见第 8 节。

不提供撤销关闭提示或最近关闭入口；需要再次展示时通过添加或原有插件入口重新打开。

## 5. 卡片桌面的唤起与收起

### 5.1 唤起入口

- 保留现有卡片桌面快捷键；快捷键在鼠标所在屏幕展开。
- 普通桌面顶部居中设置一段窄触发区，以淡色短横线提示入口。鼠标移入时提示「打开卡片桌面」，单击后在该屏幕展开。
- 触发区仅在普通桌面露出时响应。应用窗口和任务栏优先接收操作，不截获应用的标题栏、标签页或任务栏点击。
- 触发行为是单击桌面区域，不要求新增常驻顶部工具栏，也不改成悬停即展开。
- 顶部入口默认开启，允许用户在设置中单独关闭；关闭后保留快捷键和托盘菜单中的「打开卡片桌面」。
- 一次只在一块屏幕展开卡片桌面，其他屏幕保持正常使用。

顶部触发区的具体宽度、高度和提示样式属于实现细节，需验证桌面图标、框选、不同 DPI 及顶部任务栏情况下的操作。

### 5.2 收起入口

- 点击卡片桌面空白区域。
- 点击卡片桌面的关闭／返回入口。
- 使用现有快捷键或 `Esc`。

菜单、弹窗、输入法组合输入等当前交互优先处理 `Esc`；点击面板、拖动或操作内部控件不能被误判为空白点击。收起只隐藏，正在执行的任务继续，编辑内容和操作状态保留。

普通失焦不会收起卡片桌面，操作其他屏幕时仍保持打开。明确打开外部应用或选择「独立窗口打开」时，收起卡片桌面并显示、聚焦目标，避免目标被整屏界面遮挡。

### 5.3 宿主弹层优先级

2026-11-12 用户实测发现：剪贴板历史窗口会遮住点击「＋」后打开的新增面板。已确认采用复用现有宿主窗口的方案，由宿主统一管理临时弹层优先级；本节为待实施要求，不表示遮挡问题已经修复。

- 新增面板是卡片桌面的模态操作。打开时，现有宿主窗口的遮罩和新增面板一起位于本次卡片桌面的全部插件窗口之上，搜索框获得焦点。
- 面板打开期间，底下卡片保留页面、位置、输入和业务任务，但暂不可点击或获得键盘焦点。插件刷新、恢复或窗口激活不能越过宿主弹层抢到前面。
- 取消或关闭新增面板后，恢复先前的卡片相对层级和焦点；原焦点目标已关闭或不可用时，回到顶部添加入口。第一次 `Esc` 关闭面板，再次 `Esc` 才收起卡片桌面；输入法组合输入仍优先处理。
- 选择添加后，等待新卡片准备好再关闭新增面板并定位新卡片；处理中避免重复提交，失败在原面板提示并允许重试。已经创建的业务内容继续按稳定标识恢复，不能为重试重复新建。
- 顶部菜单、「更多插件」和面板列表等宿主弹层共用优先级规则。普通菜单仍沿用自身的点击外部关闭和键盘行为，不统一改成模态面板。
- 该优先级仅在当前卡片桌面会话和弹层存续期间有效，不写入面板排列，不改变普通桌面置顶设置，也不关闭、重载或重建插件窗口。收起整个卡片桌面时一并清除弹层状态。

## 6. 布局与顶部插件图标

卡片桌面采用自由排列画布，支持拖动、边缘缩放和对齐吸附。允许重叠，不强制排成固定网格；提供面板列表定位和「整理布局」。新增面板优先放在可见空位，点击后将其放到其他面板前方。

各窗口使用同一套排列和关闭规则。缩放按窗口声明提供，须尊重最小可用尺寸，不能通过缩小破坏内容操作，也不提供面板最大化。

顶部插件图标按卡片桌面已添加的内容动态生成：

- 使用插件自己的图标，不再固定显示便签、流量、截图图钉、uTools 四个分类。
- 没有加入内容的插件不显示图标。
- 同一插件的多个面板共用一个图标，单击显示并抬前这一组，不通过反复单击来整组收起。
- 通过菜单执行「收起这一组」；同组多个面板可以通过列表定位。
- 收起某组面板不删除添加记录，再次显示恢复原布局。
- 顶部图标用于控制已有面板，「＋」用于添加新面板。
- 放不下的图标收进「更多插件」菜单，保留分组操作和具体面板定位；顶部始终保留添加、面板列表和关闭入口，不把图标挤成难以点击的小按钮。

## 7. 共用布局与基本防越界

卡片桌面跨屏使用同一份内容清单，以及同一套位置和尺寸，不为每块显示器分别保存一份排列，也不因换屏展开创建额外实例。

- 点击哪块屏幕的桌面顶部，就在该屏展开；快捷键在鼠标所在屏展开。
- 位置以当前卡片桌面的可用区域为参照，换屏时保持相同的相对原点和尺寸，不能直接套用另一块屏幕的系统绝对坐标。
- 屏幕尺寸、DPI 变化或屏幕断开时，只做基本防越界，临时调整位置，使标题栏或插件声明的拖动区可达，卡片桌面面板列表的关闭等管理入口保持可用。
- 如果窗口本身大于当前可用区域，不承诺将全部内容缩进屏幕，仍尊重窗口声明的尺寸限制；允许按能力手动缩放。不增加滚动画布、宿主缩放容器或自动响应式布局系统，也不新增面板最大化。
- 临时适配不覆盖保存的原布局；回到能容纳原布局的屏幕时恢复。
- 用户主动拖动、缩放或执行整理布局时，才更新共用布局。

普通桌面与卡片桌面的布局记录相互独立。这里的“共用一套”仅指卡片桌面跨屏的一致性。

## 8. 窗口复用、uTools 兼容与便签

### 8.1 复用顺序

官方、第三方和 uTools 按实际能力接入统一窗口目录。插件可以没有窗口；有窗口也不要求提供完整和精简两种外观。宿主或兼容适配层只将插件实际支持、明确允许加入的窗口提供给卡片桌面，不能根据“这是一个插件”推断它必须有可添加窗口。

普通打开先根据来源确定目标环境，再按以下顺序处理：

1. 查找目标环境中匹配插件、窗口类型及所需内容标识的已有实例，优先复用并定位。
2. 允许多个实例、但目标环境没有匹配窗口时，在目标环境新建；不为了避免创建而搬走另一环境中的独立实例及其操作状态。
3. 声明单实例，或声明按文档／内容标识唯一复用的窗口，在目标环境无匹配实例时跨环境查找；找到则接入原实例，否则创建并绑定相应标识。

主动「添加」遵循窗口声明：允许多个实例时创建新实例；单实例仍复用；新建便签先创建新的内容标识，再按该标识管理编辑器。普通打开不能把“新建便签”这类明确的新建操作改成定位旧便签。

不同窗口类型可以同时存在，例如流量详情和网速悬浮窗共用采集后台，而不共用一套界面状态。

### 8.2 接入、归还与展示归属

单实例且已加入清单的窗口，进入卡片桌面时自动接入原界面，不增加“在这里使用”的手动确认。不强制复制页面，不将镜像画面当作拥有独立操作状态的另一个窗口，也不承诺嵌入任意外部原生程序窗口。

| 窗口来源或操作                         | 收起卡片桌面及后续行为                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 从普通桌面借用已有窗口                 | 恢复原普通桌面展示的位置、尺寸、置顶和可见状态，保留页面内容及任务；卡片桌面中调整的布局单独保存 |
| 仅在卡片桌面创建，没有普通桌面展示关系 | 收起后隐藏并保留实例状态，不能突然出现在普通桌面                                                 |
| 明确选择「独立窗口打开」               | 建立或复用普通桌面展示并聚焦，卡片桌面记录仍保留；以后按普通桌面已有窗口的规则接入与归还         |
| 关闭卡片桌面中的某一处展示             | 取消该处记录；仍有普通桌面展示关系的实例恢复原展示，没有其他展示需求时按关闭保存流程处理         |

窗口实例生命周期与展示记录分别管理，关闭一处不能误关另一处正在使用的实例；未保存内容保护不因接入、归还或关闭而取消。

### 8.3 uTools 兼容声明

- Spark 原生插件通过自己的窗口声明公开可添加项。旧 uTools 包无需修改原始 `plugin.json`，由兼容适配层生成等效的受管理窗口声明，再按同一规则进入目录。
- 适配依据原包入口、功能激活信息和兼容壳实际支持的界面能力，只有能够可靠接入的业务窗口才声明支持卡片桌面；未适配的窗口保留原有普通桌面和启动器使用方式。
- 同一插件的多个 feature 共用 runner 主窗口时，按一个可复用窗口管理，保留当前 feature 及其激活信息；不能把每个 feature 自动声明为可同时操作的独立窗口，也不能因为有多个命令而启动多份相同界面。
- 无 `main` 的包可能由兼容壳显示列表界面，不能仅据缺少 HTML 主入口判断它没有窗口；是否提供可添加项仍由适配层依据实际支持能力生成声明。
- 等效声明不改变原包业务数据和运行语义，窗口的单实例接入、归还及恢复同样遵守本节规则。

### 8.4 便签窗口

便签采用明确的特殊规则：**多处展示、单处编辑**。

- 同一篇便签可在不同位置显示多张卡片，共享正文数据。
- 插件声明便签管理、单条便签等窗口类型，都可允许加入卡片桌面，不为单条便签另建宿主卡片类别。
- 卡片桌面「＋ → 便签 → 单条便签」只新建便签；已有便签从便签管理中选择并添加。
- 同一篇便签只保留一个编辑器，点击编辑时定位并复用，不重复创建该便签的编辑器。
- 从卡片桌面新建或编辑，编辑器留在卡片桌面内。原编辑器已有普通桌面展示时临时接入，收起后恢复原展示；只在卡片桌面创建的编辑器收起后隐藏，不自动弹到普通桌面。编辑器作为业务窗口保留展示记录，用户关闭才移除。
- 保留便签现有卡片展示、折叠、贴边和展开能力。关闭卡片不删除便签，收起卡片桌面不丢失编辑内容。
- 恢复已创建的便签面板使用原便签 ID，不再次执行新建。便签被业务流程明确删除后，清理所有环境中指向该 ID 的展示，见第 9 节。

## 9. 停用、故障与启动恢复

| 情况                   | 行为                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| 收起卡片桌面           | 隐藏展示，保留已加载界面和任务                                                                 |
| 关闭其中一个面板       | 删除该展示记录，保留业务数据与其他展示                                                         |
| 插件停用               | 保留它在卡片桌面的位置和尺寸，以停用占位展示，提供启用和关闭入口                               |
| 插件崩溃或无法启动     | 保留布局，以错误占位展示，提供重试和关闭入口                                                   |
| 普通查询或业务操作失败 | 在原界面显示错误，不把整个面板当作插件崩溃                                                     |
| 插件重新启用或重试恢复 | 恢复原位置与尺寸，不自动启用用户已停用的插件                                                   |
| 业务内容被明确删除     | 关闭普通桌面和卡片桌面中指向该内容标识的全部展示，清理对应布局记录；其他内容及插件管理窗口保留 |
| 插件卸载成功           | 清理该插件的全部展示及布局记录，不保留“插件未安装”占位；重装后需要重新添加                     |

停用仍经过保存与停止流程，保存失败不能强行终止业务进程。用户明确关闭停用或故障占位时，才取消那一处展示记录。

业务删除或卸载被取消、失败时，不提前清理展示。删除业务内容由插件业务流程负责；卸载时是否删除业务数据由卸载流程单独处理，不能将清理展示及布局等同于删除业务数据。

应用重启或开机自启后的恢复规则：

- 普通桌面窗口按各自的恢复声明及原设置决定是否启动恢复，并保存、恢复位置、尺寸和置顶状态。网速悬浮窗、单条便签等可按原有明确的恢复设置启动，不根据窗口外观、尺寸或标题栏显隐推断恢复策略，不建立额外的“固定到桌面”状态。
- 恢复卡片桌面的添加清单和布局，默认不自动展开卡片桌面。
- 卡片桌面的业务窗口在首次展开时按需加载；加载过后收起只隐藏。因内部业务导航新打开的窗口也按同样规则保留，临时弹窗不恢复为长期面板。
- 未配置自动恢复的普通窗口不因曾经打开就自动弹出；未保存内容需具备草稿恢复能力。
- 恢复只打开已保存窗口或业务内容，不执行首次添加时的新建动作；重试同样不能产生重复便签或其他业务数据。
- 剪贴板记录、流量采集等后台能力按插件自身设置运行，不以卡片桌面是否展开作为启停条件。

## 10. 实施边界与旧行为调整

本次是显示架构和交互调整，不只是修改按钮名称。实施时需要覆盖以下边界：

1. 建立插件命令、窗口定义、窗口实例和展示关系的统一框架；插件允许无窗口，启动器读取公开命令及快捷操作，卡片桌面只读取声明可添加的业务窗口。
2. 在窗口声明中统一表达可添加性、用途、尺寸、标题栏、复用、创建入口与恢复参数，按“插件 → 窗口”生成添加目录，兼容现有承载实现。
3. 为卡片桌面建立独立添加清单，将当前“关闭插件栏再激活普通窗口”改为在内部添加；普通打开先复用目标环境，主动添加按能力新增；创建与恢复分开，便签绑定稳定内容标识。
4. 将固定分类替换为按实际插件身份分组的动态入口。
5. 按窗口提供默认显示完整标题栏、插件声明可隐藏且用户不可覆盖的规则；窗口能力与环境约束共同决定操作，覆盖官方、Web 插件和 uTools。
6. 接入便签单编辑器复用、其他单实例窗口的接入与归还，区分借用与仅属于卡片桌面的实例，保留页面和原展示状态；uTools 由兼容层生成等效窗口声明。
7. 增加普通桌面顶部点击入口，保留快捷键；接入共用布局及基本防越界，不增加复杂的分辨率适配。
8. 将历史常驻桌面配置迁入普通桌面窗口及置顶等属性，保留插件栏排列和业务数据；不把历史配置当成已验证的新行为。
9. 统一打开来源：启动器默认普通桌面，插件内部仅对声明支持的目标跟随卡片桌面；业务窗口长期保留，设置、确认和文件选择等临时交互不加入清单。
10. 菜单由插件控制，宿主提供窗口菜单及操作 API；内容删除、插件卸载成功后清理关联展示和布局，停用或故障保留占位。
