# 桌面插件栏复用窗口：隔离原型评估

2026-11-03。本文记录正式接入前的隔离原型与对照测量。原窗口复用代码随后已接入，见[桌面插件栏实现说明](../desktop-widget-layer.md#17-游戏栏式桌面插件栏2026-11-01)；用户要求关闭程序、暂停测试，最终运行验收尚未完成。

## 建议

优先复用各插件的原窗口与界面树，选择一个已有的可信桌面层窗口，临时展开为遮罩和工具栏的承载窗口；其他原窗口提升到遮罩之上。退出时恢复原尺寸、位置、置顶、聚焦和穿透状态。插件栏的位置记录仍独立，不写回普通桌面位置。

这不要求跨进程共享 DOM。每个插件始终保留在自己的 WebContents 中，管理模式只改变原生窗口的呈现与坐标。没有可用可信宿主、宿主不在目标显示器等情形，需要在正式接入时明确宿主选择与空态行为；不把任意 Web 插件页面升级为管理宿主。

## 实测条件与结果

- Windows，Electron 45.1.0，单显示器，工作区 1920×1032，缩放 100%。
- 使用项目现有 `LayerWindow` 与 `LayerCardContent`、`DeclarativeCard`、`CapsuleHost`、`ScreenshotCard`。
- 三个合成插件：110×46 流量卡、便签胶囊、使用本地生成 3840×2160 PNG 的贴图。另有一个受控参考窗口，用于原生输入、可见性与穿透检查。
- 后台数值为每秒刷新的本地 fixture，没有启动另一套流量采集、调用真实便签或改变用户业务数据。
- 每种方案两次，正序与倒序各一次；均在同一隔离 Electron 进程内测量。私有提交量来自 `app.getAppMetrics().memory.privateBytes`，不含显存。渲染器数量包含参考窗口，所以桌面基线为 4。

| 方案                         | 打开时新增渲染器 | 私有提交量增量  | 模式切换至界面可见 |
| ---------------------------- | ---------------- | --------------- | ------------------ |
| 独立窗口重新展示全部内容     | 1，关闭后回收    | 121.6–125.6 MiB | 304–368 ms         |
| 原插件窗口复用，另建管理窗口 | 1，关闭后回收    | 77.3–97.6 MiB   | 296–332 ms         |
| 已有窗口临时承载管理层       | 0                | 4.2–23.3 MiB    | 35–86 ms           |

时间测量终点为布局提交及 DOM 可见，不包含显示器刷新延迟。这些数值是隔离原型的两次采样，受 Chromium/GPU 缓存、垃圾回收与采样时机影响，不能作为正式包的固定预算。CPU 采样不足以证明三种方案有显著差异；本轮明确的收益是减少一个渲染进程及缩短窗口创建等待。

## 功能检查

- 全部六次对照中，三个原窗口的 PID、WebContents ID、DOM 节点身份与挂载次数保持不变；三个组件各挂载一次。
- 最终版本额外连续打开／关闭六次，节点与原生窗口身份仍保持，图片加载次数保持一次。
- 受控指针输入实际触发便签拖动，插件栏位置从 `(430,250)` 移到 `(530,316)`；普通桌面位置不变。退出后恢复原生尺寸、位置、focusable、置顶和穿透状态。
- 使用 Windows `computer-use` 做过 F8 呼出、便签拖动与 Esc 退出的原生输入观察，并检查恢复后的画面。最终拖动逻辑改为在小窗口内直接移动原生窗口，使用定向 Chromium 输入复测，再核对真实窗口 bounds。
- 原生图片穿透测试点击抵达受控参考页面，计数增加。参考窗口在对照期间保持可见并持续产生动画帧。
- 最终采集的流量、便签和贴图窗口图片完整，没有观察到之前的裁剪残留。

## 必须保留的切换约束

早期原型只修改 bounds 时，透明窗口从大区域缩回后出现过旧裁剪区域与画面不一致。最终原型采用以下顺序，最终对照及连续切换的提交等待超时为 0：

1. 暂停展示并清除旧原生裁剪区域。
2. 更新窗口尺寸、坐标与新裁剪区域，保留原 WebContents、绑定和 React 节点。
3. 向界面发送新的布局版本，等待 React `useLayoutEffect` 返回该版本已经提交的确认。
4. 恢复展示与聚焦。正式实现中，确认失败应恢复旧状态，不继续展示不完整的布局。

小工具窗不能仅在其内部用 CSS transform 预览大距离拖动，否则内容会越出原生边界被裁掉。最终原型对这些窗口按屏幕坐标移动原生窗口，松手再确认独立布局；承载遮罩的全屏窗口内可以继续使用 CSS transform。

正式接入应通过现有窗口协调器串行切换，保持 source owner、surface generation、IPC seq、截图授权和业务生命周期边界。管理操作只能授予本次可信宿主及选中的参与窗口；跨显示器、混合 DPI、锁屏、全屏游戏、宿主故障及外部应用最终获得焦点仍需专项验收。

- `main.cjs`、`preload.cjs`、`ui/stage.tsx`、`build.mjs`：独立测试宿主和复用的实际 UI。

- `qa-final.json`、`qa-final.log`：最终拖动、连续切换、身份与状态恢复检查。
- `native-promoted-host-traffic.png`、`native-promoted-host-note.png`、`native-promoted-host-image.png`：原型窗口自身的截图，仅包含测试内容。
- `events.json`：模式、位置和提交超时事件。
