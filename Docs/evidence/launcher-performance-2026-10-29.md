# 启动器常驻与响应优化（2026-10-29）

## 完成的行为

1. 主启动器的 Esc（先清空输入）、界面 ×、失焦及窗口关闭操作保留窗口；应用退出时仍正常释放。独立插件工作区继续经过保存确认后释放。隐藏会撤销查询和旧结果权限，宿主拒绝隐藏窗口发来的迟到查询。
2. 应用初始化后以 `visible:false` 预加载启动器。预加载会准备语言、主题和命令目录，不会执行搜索或抢占外部焦点。页面就绪时会补发仍由宿主持有的选区请求，避免与初始读取交错时丢失交付。
3. 页面入口按路由动态加载；启动器的 OCR、翻译、剪贴板、搜索和截图工作区，以及搜索预览，按需加载。`desktop_ready` 在相应懒加载页面提交后发送。
4. 粘贴目标捕获绕过剪贴板历史/图片处理队列，与选区读取并行，单次等待上限为 150 ms。超时或新目标捕获后，旧粘贴操作被拒绝；迟到的确认不能恢复已经失效的目标。目标不可用时仍可以复制后手动粘贴。
5. 前端立即提交查询；本地命令及应用搜索不等待统一的 100 ms 防抖。其他插件的非空查询在宿主侧保留 100 ms 可取消等待，取消后不会启动旧查询。结果继续使用已有增量返回协议。

## 真实 Windows 验证

开发模式中通过正常保存退出流程重启 Electron，使用本地 Chromium 调试连接检查实际主进程、preload 和 React 页面。

- 预加载 URL 包含 `view=launcher&preload=1`；首次原生进程窗口检查没有可见主窗口。Electron 页面初始 `document.hidden` 曾返回 false，因此使用原生窗口状态和宿主显示/隐藏事件交叉验证，没有依赖该值判断预加载是否显示。
- 主启动器实际加载资源中没有 `MainWindow`、`NotePad`、`SettingsWindow`、`OcrWorkspace`、`TranslationWorkspace` 或 `SearchWorkspace` 页面模块。
- 5 次显示/聚焦/隐藏复用同一个 Chromium target。Esc、×、失焦均保留该 target。
- 最终一次 5 次显示/聚焦至下一动画帧的采样：15.3、11.0、16.8、31.4、26.7 ms。该计时不包含 UIA 选区读取、物理按键传递或系统合成器呈现，不能当作端到端热键延迟。
