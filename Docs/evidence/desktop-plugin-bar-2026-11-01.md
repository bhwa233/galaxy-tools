# 游戏栏式桌面插件栏：实现与验证

日期：2026-11-01（Asia/Hong_Kong）。范围：现有桌面便签／胶囊、流量 HUD、截图常驻图钉。

## 使用入口与行为

- 默认快捷键 `Ctrl+Alt+D` 呼出／收起插件栏，在设置 → 快捷键中可录制修改或清空停用。旧配置缺失字段时补默认，明确保存的空字符串保持停用。
- 桌面插件层、便签接入和 Web 卡片默认开启；设置 → 桌面卡片提供“打开插件栏”按钮，托盘菜单也提供“桌面插件栏”。用户明确关闭后可在设置中重新开启。
- 启动期间通过快捷键、托盘或设置呼出插件栏，会等待插件宿主初始化及桌面呈现恢复完成。初始化失败、布局读取失败和用户关闭分别报告对应原因，避免将尚未就绪误报为未开启。
- 插件栏显示在鼠标所在显示器的工作区：原工作界面上方的半透明暗色背景、顶部居中工具栏、可自由拖动的面板。
- 工具栏提供便签／流量／截图分类开关、各实例的面板列表、时间、桌面设置和退出。
- 每个插件在悬停或键盘聚焦时显示外侧的拖动、设置、图钉和收起工具条，工具条不占插件内容尺寸；菜单中可以改变常驻时的置顶和鼠标穿透状态。操作模式内始终可交互。
- Esc、再次按快捷键或点击背景退出。菜单和拖动先处理自己的 Esc，避免误退。打开详情／编辑时退出操作层并把焦点交给新窗口。
- 流量、便签和贴图共用普通桌面的 `LayerCardContent` 渲染入口，沿用原组件、主题和当前尺寸。流量悬停排行共用插件的声明式模板和图标数据；便签显示原胶囊并进入原编辑器；贴图沿用已有显示、缩放、适合屏幕和编辑能力。

这里只列出当前桌面层提供的实例。便签编辑器等独立业务窗口继续使用既有窗口入口；桌面胶囊中的队列控制项、临时预览和拖动投影不会被当作额外插件面板。

## 状态与资源边界

`DesktopLayer` 提供可信操作层投影。现有业务实例和采样保持一份，流量数据帧广播给当前有权展示该卡片的视图；未接入任意第三方 Web 小组件的多会话呈现。

目标屏幕原桌面 surface 在操作层显示期间暂时隐藏，退出后恢复。临时呼出不修改原来的位置、显示和输入设置；用户明确改变置顶／穿透时，流量和贴图写回现有插件配置。便签展示使用宿主的呈现设置。

插件栏布局独立保存到配置目录的 `desktop-overlay-layout.json`，按实例和显示器记忆。便签使用业务 `renderRef` 保持布局身份，桌面队列或显示位置改变不会丢失其插件栏布局。原子写入失败不提前提交内存状态；坏布局文件保留并阻止插件栏写入，不阻止普通宿主启动。

拖动在 renderer 中通过 rAF 和 CSS transform 预览，只在结束时发送一次布局提交；支持标题聚焦后的方向键移动。修改插件栏排列不会改变原 Windows 桌面卡片的几何。

操作层保留原有 sandbox、context isolation、受控 preload 和按 surface／generation／seq 的 IPC 校验。截图资源按每个可信 surface 自己的快照独立授权。关闭后的旧 IPC 身份不能修改新会话。锁屏、休眠、禁用桌面层或操作层故障会退出操作层，恢复普通桌面呈现。

焦点恢复复用现有 warm native helper，只允许恢复本次实际采样到的 HWND／PID／进程生命周期，且只消费一次。打开详情、切换其他应用、锁屏等路径不恢复旧窗口；不使用 AttachThreadInput、模拟激活按键或最小化其他应用。

最终报告：[report.json](../../local-build/desktop-overlay-validation/smoke/runs/c9dfa9a2-cc23-42f4-8786-804a7266f867/report.json)。截图：[三类面板](../../local-build/desktop-overlay-validation/smoke/runs/c9dfa9a2-cc23-42f4-8786-804a7266f867/overlay-three-panels.png)、[重新呼出后恢复](../../local-build/desktop-overlay-validation/smoke/runs/c9dfa9a2-cc23-42f4-8786-804a7266f867/overlay-restored.png)。截图来自透明操作层的 `capturePage`，不包含下方用户桌面，查看器中的黑色区域不代表产品使用不透明背景。

真实 Electron 检查使用生产 DesktopLayer、LayerWindow、WidgetHost session／协议、preload、UI 和 ShortcutManager；便签／贴图／流量内容明确为合成 fixture。使用隔离快捷键 `Ctrl+Alt+Shift+F11` 经系统键盘事件触发真实全局注册，避免占用用户当前的常用组合键。

20 项覆盖：全局快捷键呼出与再次按同一快捷键收起、可聚焦无系统栏沙箱窗口、鼠标所在屏幕、字体加载、截图授权、穿透贴图在操作层内缩放、实时数据广播、拖动只在结束提交且原桌面几何不变、菜单优先处理 Esc、收起保留数据、置顶／穿透选择、旧 IPC 失效、重新呼出恢复、详情焦点交接、背景退出、副屏原生 DIP 工作区、锁屏与禁用释放。第二次快捷键关闭同样通过真实系统键盘事件触发现有全局注册和回调；这项与原生外部窗口最终取得焦点的验证分开记录。已目视检查顶部工具栏和三个面板。

外部焦点的正向原生恢复仍未证实：helper 采样没有匹配专用外部测试窗口的 HWND，harness 将恢复目标严格置零，没有尝试恢复其他用户窗口。已验证退出会请求恢复、详情路径不会请求恢复，以及未采样／过期目标拒绝；这些不能替代真实外部窗口最终取得焦点的验收。物理鼠标手感、真实游戏全屏和本轮混合 DPI 全矩阵也未实测。

当前构建产物已经更新；运行中的旧宿主实例需要重启后加载新快捷键和宿主接线。本轮未运行 Windows 安装器打包或发布。

## 默认开启与启动期间呼出的回归修复

默认值及当前开发配置的 `enabled`、`notesEnabled`、`webEnabled` 均已为 `true`。用户遇到的“请先在设置中开启桌面插件层”来自启动门禁：插件安装期间已注册快捷键，但 `layerStartupReady` 尚未开放。呼出请求现在等待首次桌面同步完成；插件宿主初始化失败会返回独立错误，布局读取失败和对象退出也不再报告为开关关闭。

隔离生产宿主回归：[report.json](../../local-build/default-on-startup/runs/early-overlay-20261101-b/report.json)、[时序摘要](../../local-build/default-on-startup/runs/early-overlay-20261101-b/early-overlay-summary.json)。真实快捷键回调在第一个官方插件启动前触发，当时尚无 launcher；经过本次全新 profile 安装和初始化，41.366 秒后真实插件栏窗口可见，5 项检查通过，错误弹窗和 renderer errors 均为零。该时间仅代表此次隔离冷启动，不代表日常启动耗时。探针调用实际注册的回调，没有注入系统按键，也没有改写用户开发 profile。

开发启动器同时补全对 `quicklinks/backend.mjs` 的生成产物排除。此前该文件在插件构建时被重复写入，又被监控为源码变化，形成反复重建与重启，持续打断初始化。修复后与既有便签、剪贴板和流量后端构建产物使用同一排除规则。
