# 常驻选区读取试验（2026-10-29）

选区辅助程序新增常驻请求模式，空闲时等待 stdin，只在收到带请求 ID 的读取命令时调用 Windows UI Automation。宿主启动时预热辅助程序；正常读取复用进程。取消、超时或无效响应会回收该辅助程序，下次请求重新启动。宿主退出时关闭通道；宿主异常退出时辅助程序随之退出。原有一次性命令保留用于同机对照。

本次没有改变启动器窗口的隐藏/销毁策略，也没有增加鼠标监听、选区轮询或剪贴板回退。

## 实测范围

- Windows Node 26.12.1，pnpm 12.15.0；生产 `NativeSelectionReader` 和真实 C# 辅助程序。
- 对照来自同一份 C# 程序：一次性模式 12 次、常驻模式 40 次。常驻模式中所有请求复用同一个 PID。
- 计时是辅助程序读取链路，包含宿主请求与解析；不代表物理快捷键至启动器完成绘制的总延迟。
- 固定 WPF 样本额外验证正确选区、空选区、密码框，以及剪贴板序号不变。没有记录用户选区内容。

| 指标                             | 实测                    |
| -------------------------------- | ----------------------- |
| 一次性模式中位数                 | 289.95 ms               |
| 常驻模式中位数                   | 25.94 ms                |
| 常驻模式 P95（含首次读取）       | 31.43 ms                |
| 首次常驻读取                     | 155.59 ms               |
| 常驻读取后工作集 / 私有提交内存  | 47.65 / 33.80 MiB       |
| 约 10.43 秒空闲期间 CPU 时间增量 | 0 ms                    |
| 固定 WPF 样本首次 / 后续读取     | 89.25 ms / 4.04–5.78 ms |

内存为一次进程快照，空闲 CPU 为短时间采样；没有完成长时间内存稳定性测试。UIA 仍依赖目标应用响应，修饰键释放等待和 2.5 秒读取超时仍保留。

原始报告位于 `local-build/selection-resident-evidence/report.json` 和 `ui-report.json`。本地探针分别为 `local-build/selection-resident-probe.mjs` 和 `local-build/selection-resident-ui-probe.mjs`，后者复用已有 WPF fixture。
