# P1V 原生合同与初始预算

日期：2026-10-24。P1V 只证明原生链路可被宿主管理，不代表正式七插件已交付。

## 实际链路

- [截图/OCR](spark233-native-capture.md)：固定源码和依赖构建成功；用户拖选四行人工样例后，ScreenCapture 会话 `ca411343f4f34b418c9701a9326a5191` 导出 810×485 PNG，管理入口校验结果后调用 ImageReader，同一会话识别四行，两进程退出码 0。未改变 TOOLWINDOW 样式。
- [Pulse](spark233-native-search.md)：独立文件名和 Instant 正文查询、受限调用者可见性、取消替换与退出通过；不是 SYSTEM 全卷服务验收。
- [剪贴板](spark233-native-clipboard.md)：受控格式读取、文件引用、敏感标记和通知停止通过，四格式原始快照回放一致；Electron 运行时成功加载 addon。连续单格式 setter 会丢失其他格式，因此正式回放需要薄原生桥。

## 对宿主合同的影响

- 每次原生任务有独立会话目录，绑定插件实例、精确版本和原生 PID；结果还要校验协议版本、动作和会话。禁止读取任意剪贴板变化作为截图结果。
- 当前 PNG 在同一会话传给 OCR；先原子发布结果，宿主确认后再转交持久资源。取消、超时和退出不使用其他会话的旧结果。
- 主进程登记原生任务及后代，退出要确认资源释放；强制终止只能证明回收，不可代替业务保存或正常取消确认。插件停用/更新先询问未保存状态，再停止任务并隔离晚到结果。
- backend、native、剪贴板、文件等能力写入插件清单。第三方 Node/native 执行需要显式信任；进程隔离不能被宣传成权限沙箱。客户端执行已验证入口和受控参数，不执行 npm 生命周期脚本。
- Pulse 的服务与调用者权限保持分离。正式服务安装、全卷覆盖和正文范围同步继续在 P5 完成；已有 restricted-token fixture 证据不扩大为 SYSTEM 服务保证。
- 剪贴板恢复需要一次打开范围中的多格式事务，预览与原始字节分离；敏感标记在捕获前检查。原型中途失败恢复和正式回贴焦点在 P6 补齐。
